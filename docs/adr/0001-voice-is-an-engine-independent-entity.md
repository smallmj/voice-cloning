# 音色是独立于引擎的逻辑实体，引擎绑定只是可重建的缓存

用户说的「音色预设」（头像 + 文字说明 + 参考音频）本质上描述的是**一个声音身份**，而不是某次 API 调用的配置。因此「音色」被建模为一个独立实体，它下面挂 N 个「引擎绑定」（每个引擎各自的云端 voice_id、上传状态、参数、可用性）。头像是音色的属性，不是引擎绑定的属性。

**这是数据模型里最难回头的一处**：若把音色绑死在单一引擎上，将来无法表达「同一个音色换引擎唱一遍」（多引擎交叉试听——本产品最核心的差异化），也无法解释为什么同一个声音在 ElevenLabs、本地模型和 MiniMax 上各有不同的 ID。

**决定性论据（来自调研）**：云端音色会被厂商静默回收——MiniMax 音色 7 天未调用即删除、百度音色 1 年无合成调用自动删除、华为云单账号上限 1000 个音色。如果音色预设只存一个云端 ID，它会无声失效。因此**本地参考音频才是真相来源，云端 ID 必须被视为可重建的缓存**，并需要「音色健康检查 → 绑定失效则自动重传重建」的机制。

**Considered Options**: 引擎绑定模型（一个预设 = 某引擎 + 参考音频 + 参数）实现更简单，但正是 voicebox（★54k）与 VoiceStudio（★31k）都绑死单引擎所留下的最大市场空白。
