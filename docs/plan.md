## 1. 产品定义

**一句话**：一款 macOS / Windows 桌面应用，把**云端 API** 与**本地模型**编排进同一个工作流，用同一套音色完成文字转语音、声音复刻与音色设计。

### 差异化（三条，均可从竞品证据推出）

**① 跨引擎的统一音色资产。**
两个头部竞品都绑死单引擎：voicebox（★53,982，MIT）与 VoiceStudio（★31,227，AGPL-3.0）的 profile 各自只对应一个引擎。本产品的音色是**引擎无关的逻辑实体**，下面挂多个引擎绑定——因此「同一个音色换引擎唱一遍」这件事，在它们的数据模型里根本无法表达。

**② 引擎能力中立层。**
voicebox 的抽象泄漏是有据可查的反面教材：副语言标签 `[laugh]` 只有 1/7 引擎支持，其余引擎**把它当文本念出来**；`instruct` 字段在 UI 广泛暴露却被多数引擎静默丢弃（issue #185，全仓库互动最高）。本项目的原则是**能力声明必须真正控制 UI 可用性**——引擎不支持的能力，界面直接不给。

**③ 中国大陆可用。**
voicebox 官方 troubleshooting 对大陆用户的答案原文是「Try using a VPN if HuggingFace is blocked in your region」；#546 / #741 两条中国网络 issue 至今 open 无人回应；社区已写好完整 ModelScope 支持（PR #1075）晾了 3 周未合。**「装完就能用、不要求用户有代理」在这个赛道是真空。**

### 三条明确的非目标

- **不做远程推理**（ADR-0005）：每台机器各跑各的，跨机器靠手动导出。
- **不内置平台密钥代调用**（ADR-0003）：一律 BYOK。
- **不做账号体系与云同步**（ADR-0003 / ADR-0005）：全本地存储。

## 3. 架构

```
┌─────────────────────── Electron 外壳 ───────────────────────┐
│  React UI（4 标签页）                                        │
│  波形：wavesurfer.js / peaks.js                              │
└───────────────┬─────────────────────────────────────────────┘
                │  本机 HTTP + WebSocket（日志/进度）
┌───────────────▼─────────────────────────────────────────────┐
│  Python 推理服务（sidecar，127.0.0.1:动态端口 + bearer 鉴权） │
│  ┌────────────┐ ┌──────────────┐ ┌───────────────────────┐  │
│  │ 引擎注册表  │ │ 文本归一化层  │ │ 任务队列（限流/显存）  │  │
│  └────────────┘ └──────────────┘ └───────────────────────┘  │
│  ┌─────────────── 云端适配器 ───────────────┐                │
│  │ 阿里百炼 │ MiniMax │ Fish Audio          │                │
│  └──────────────────────────────────────────┘                │
│  ┌─────────────── 本地适配器 ───────────────┐                │
│  │ macOS：Qwen3-TTS-0.6B（MLX，torch-free） │                │
│  │ Windows：待定（PyTorch + CUDA）           │                │
│  └──────────────────────────────────────────┘                │
└──────────────────────────────────────────────────────────────┘
                │
        数据目录（自包含、可整体拷贝）
        SQLite + 音频文件 + 音色元数据
```

**为什么 macOS 与 Windows 用不同运行时**：PyTorch/MPS 对 TTS 曾被认为基本不可用（`nn.Conv1d` 的 65536 输出通道上限，IndexTTS 在 M3 Max 上复现；GPT-SoVITS 维护者建议 Mac 用 CPU；XTTS-v2 在 MPS 上 hang）。因此 macOS 起初走 torch-free 路线（MLX），Windows 走 PyTorch + CUDA，**但对上层暴露同一套协议**。**修正（2026-09-19）**：IndexTTS-2.5 在 torch 2.8 + M5 Pro 的 MPS 上实测可端到端出音频（`indextts-25-mps` 引擎，热 RTF ≈ 5.0，见 `docs/installation/macos-indextts-2.5-mps.md`）——MPS 路线对 IndexTTS-2.5 成立，只是速度只适合短句，长文本应走任务队列；其余引擎的 MPS 问题结论不变。

**必须避开的已知陷阱**

*打包与进程（来自 voicebox 事故）*
- **不用 PyInstaller 冻结 Python**——它的崩溃类别（`_MEI` 缺文件 #212、`No module named` #275、broken pipe #606、server 起不来 #513）全部源于此。
- **不在运行时下载可执行二进制**——它的做法直接导致「Windows 装 .exe 就是没 GPU」（#192）、国内下不动、被 AV 报毒。
- 半成品 `.venv` 必须清理（ComfyUI #1574：否则重试永久失败）。
- 默认只绑 `127.0.0.1` + 强制鉴权（它的 `0.0.0.0` 无鉴权 #934）。

*依赖解析（来自 IndexTTS / VoxCPM 事故，直接威胁 ADR-0002 的运行时）*
- **传递依赖会用 CPU 版 torch 顶掉 CUDA 版**。`funasr` / `modelscope` 这类依赖会从默认 PyPI 索引取 CPU-only 的 `torch`。VoxCPM #60 实测：用户装好 GPU 版后 `torch` 变成 `2.8.0+cpu`、CUDA 不可用、**29 秒音频跑了 700 秒（RTF≈24）**，反复重装无效。
  → 三条硬规范：`torch` / `torchaudio` 必须写成 **project 直接依赖**；CUDA 索引用 `[[tool.uv.index]]` + `explicit = true`，**不用 `--extra-index-url`**；**安装后断言 `torch.cuda.is_available()` 且 `torch.version.cuda` 非空，否则拒绝启动**（而不是让用户跑出 700 秒才发现）。
- **安装路径必须纯 ASCII**。IndexTTS #93：中文路径会让 ninja 生成乱码 `build.ninja` → **BigVGAN CUDA 内核编译失败并静默降级到 torch 实现**（只慢不报错）。⚠️ **本仓库自身路径 `My Projects/声音复刻软件` 同时含空格与中文**，Windows 用户还有 `C:\Users\张三\`、`C:\Program Files\`。→ **已定**：保留现有仓库路径（问题出在构建/安装目录，源码目录不受影响），但 **venv / `TORCH_EXTENSIONS_DIR` / 运行时安装根一律强制 ASCII**（如 `C:\ProgramData\VoiceClone\`）+ 编译失败要在 UI 里说明。
- **torch/torchaudio 版本漂移会静默损坏音频**。IndexTTS #724：TorchAudio 2.9+ 起 `save()` 走 TorchCodec，把 WAV **静默削顶饱和**（不报错、不告警）。→ 逐引擎钉版本、venv 完全隔离、加**输出峰值自检**。

*显存（来自 IndexTTS #630 / #649，至今 open）*
- **显存泄漏已确认且 `unload()` 不够**：连续生成后显存从 12GB 爬到上限、生成结束不释放，到顶后连短文本都变慢；用户原话「Restarting the service frees up the memory」。叠加常驻稳定占用约 10GB。
  → 三层防护：`unload()` + 空闲超时释放 + **达到次数/显存阈值时重启 worker 进程**。

## 4. 领域模型

术语以 `CONTEXT.md` 为准。核心关系：

```
音色 (Voice) ──1:N──> 引擎绑定 (EngineBinding)
   │                        │
   名字/头像/说明            云端 voice_id 或本地模型状态
   参考音频 ← 真相来源       参数
   试听样本                 可用性/健康状态
   │
   └──N:M──> 生成任务 (Generation) ──> 音频产物 + 日志
```

**三条硬规则**：

1. **参考音频是真相来源，云端 ID 是可重建缓存。** 厂商会静默回收音色——MiniMax 7 天未调用即删、百度 1 年无合成调用自动删除、华为云单账号上限 1000 个。因此需要**音色健康检查 → 绑定失效则自动重传重建**。
2. **引擎能力驱动 UI。** 能力维度：语种、复刻、音色设计、发音控制、情感、商业许可、跨设备使用、**上传内容是否用于训练**、全流程能否 API 闭环。引擎不支持的能力，界面不予显示。
3. **生成任务记录血缘。** 参数、成本、耗时、引擎与模型版本全部入账——重跑与偏好画像都依赖它。

## 5. v1 引擎矩阵

### 云端（全部 BYOK）

| 引擎 | 效果 | 价格 | 关键限制 |
|---|---|---|---|
| **阿里百炼** Qwen-Audio-3.0-TTS-Plus | Speech Arena Elo **1234（全球第 4）** | 合成 **0.8 元/万字符**（1 汉字=2 字符 ⇒ ≈0.4 元/万汉字）；复刻 **0.01 元/音色**；设计 0.2 元/音色 | 协议 4.6 明文禁转售 → 只能 BYOK |
| **MiniMax** speech-2.8 | AA Elo 1168；社区公认情感自然度第一梯队 | 合成 2.0 元/万字符；复刻 9.9 元/音色 | **T2A 充值用户仅 20 RPM**；音色 7 天未调用即删 |
| **Fish Audio** S2.1 Pro | AA Elo 1141；中文良好 | 按 UTF-8 字节计费，$15/1M bytes ≈ **$45/1M 汉字** | ⚠️ **ToS 写明上传内容可能被用于训练 AI/ML 模型** |

**MiniMax 已核实事实（2026-09-18 调研，证据见 `docs/research/2026-09-minimax-api-and-local-tts.md`）**：

- **两个区域是两套额度**：国际 `api.minimax.io` T2A **60 RPM**（单一档）；大陆 `api.minimaxi.com`（2026-09-20 实测修正，`api.minimax.cn` 仅文档站域）T2A **免费 10 / 充值 20 RPM**。**大陆付费档只有国际的 1/3**，这直接决定长文本要走异步接口（单请求上限 **100 万字符**）而不是同步分段（同步上限 <10,000 字符）。RPM 是**账号级**，不是 key 级。
- **GroupId 已不再需要**（6 个 OpenAPI 全查过，零命中），鉴权只有 Bearer。区域因此应做成**引擎级可配的 base URL**。
- **7 天删除规则确认，且带一个陷阱**：官方原文「Previewing during voice_clone does not activate the voice_id」——**复刻后的试听不算"使用"**。适配器必须在复刻成功后**静默合成一句短音频**来激活，否则用户只试听、过几天回来音色已被删。
- **首次真实合成才触发 $1.50 复刻计费**（复刻本身不计费），所以激活不额外增加成本。
- **音色设计是存在的**（`/v1/voice_design`，$3/音色，同样首次使用计费）——本计划原先假设不做，现已改为纳入范围。
- **`check_voice` 不能用列表查询实现**：`/v1/get_voice` 是 **POST**，且克隆音色**只有在成功合成过一次之后才可查询**——健康检查只能实现成探测性合成。
- **ToS 有两条落点**：数据用途（保留「为改进算法或增强服务」使用信息的权利）必须显示在披露面；**深度合成的公开标识义务落在应用侧**，而 `aigc_watermark` 参数只给复刻预览音频加提示音，**不满足**该义务。

### 本地

| 平台 | 引擎 | 实测 | 许可 |
|---|---|---|---|
| **macOS** | **Qwen3-TTS-0.6B-Base 8bit**（mlx-audio） | M5 Pro 热 RTF **0.37** / 峰值内存 **2.2 GB** / 权重 1.9 GB / 中文 ASR 复核 3/3 | **Apache-2.0，可随包分发** |
| **macOS（MPS）** | **IndexTTS-2.5**（PyTorch 2.8 + MPS，fp32） | M5 Pro 热 RTF **≈5.0**（实测 2026-09-19）；冷启动加载约 75s；本地已有权重可零下载复用（`VOICECLONE_INDEXTTS25_LOCAL_WEIGHTS`） | 同 CUDA 版：bilibili 协议；**适合短句，长文本走任务队列** |
| **Windows** | **IndexTTS-2.5**（PyTorch + CUDA） | 显存约 **6 GB**（8GB 卡可跑）；RTF **0.2065**（4090 bf16, kv_cache）；中文（2.0 版）CER 1.03 / SIM 76.5；零样本复刻**不需要参考文本转写** | bilibili 协议：MAU<1亿 且年营收<10亿人民币可商用；**基础依赖在 Windows 零编译可装** |

> **已核实（2026-09-18 参数调研）**：这句选型理由**本身是真的**——IndexTTS-2.5 确实支持发音控制，语法是尖括号标注 `<汉字|PINYIN>`、**声调数字且大写**（例：`他在银<行|XING2>里<行|HANG2>走了半天`），也接受 CMU 音素与日文假名；2.0 则是在正文里裸写大写拼音。**真正的缺口在界面**：两个 IndexTTS 引擎声明了 `pronunciation_control=True`，但**没有任何 `param_specs()`**，而界面只渲染 `param_specs()` —— 所以用户没有任何入口用它。须随参数界面一并补齐（**不是**降级为 `False`）。
>
> ⚠️ 三种发音语法互不兼容，做「规范输入 + 按引擎转换」时必须逐一对齐：**IndexTTS `<行|XING2>`**（大写声调数字）、**MiniMax `(chu3)(li3)`**（小写声调数字）、**dots.tts `hào`**（声调符号，明确不接受 `hao4`）。

- **VoxCPM2 是本轮首选**：唯一在两个平台都有官方路径的候选。
- **FireRedTTS3 走"我们维护补丁"路线 + 有界 PoC 闸门**（补丁内容：设备选择、SDPA 替换、seed 守卫、去掉 fasttext）。中文复刻指标（Seed-TTS-eval avg 3.04/78.8）与 **21 种中文方言**、以及强过现有 Qwen3-TTS-VD 的**文生音色**是它的强项；但**每一个平台能力都还停在未合并的社区 PR 上**，接它等于接下一份上游维护责任——须另立 ADR 记录这个取舍。
- **合规两条留待评审**：FireRedTTS3 的 README 有「零样本复刻**仅限学术研究用途**」声明（**不在 LICENSE 内**；Apache-2.0 §2 授予的权利不被该文字收窄，但它是作者意图的明确表述，且明显弱于 VoxCPM2 的 "free for commercial use"）；其 RedAE 训练数据含 10% 音效与 15% 音乐，**训练数据来源问题许可完全不涉及**。

### ASR

- macOS：`mlx-whisper`　Windows：`faster-whisper`
- 云端兜底：复用已接入厂商（阿里），**不新增供应商**，避免用户配第二个 key

### 两处必须显式告知用户的事实

- **Fish Audio 会上传内容用于训练**——对一个声音复刻产品，这是把用户的声音传去训练，**必须在引擎选择处显示**。
- **火山引擎 / 阿里百炼 / 科大讯飞**条款明确禁止转售（本次未选入 v1，但将来若加入，必须在能力矩阵里标注「商业使用许可」与「跨设备使用」——火山的许可限定「单一台终端设备」，与双平台使用直接冲突）。

## 6. 界面结构

**5 个区（左侧导航栏）+ 一条铁律**：实时日志**不能**单独占一个区（生成时用户要盯着它），它是「生成」区内的可折叠抽屉。决策与理由见 ADR-0013。

**为什么是 5 个而不是 4 个**：引擎管理（选择/安装/能力矩阵/降级顺序/本地模型与磁盘占用/下载源）本身就是一页的量，塞进「设置」会让设置变成第二个最长的单页——正是这次要修的病。

### 生成
- 文本输入区（含**归一化预览**——让用户看到「2025 年」被展开成什么，避免"为什么读错了"的无解困惑）
- 音色选择器（卡片式，含头像）
- 引擎选择器（**能力矩阵驱动**：不支持的选项直接禁用并说明原因）
- 参数面板（**按所选引擎动态渲染**——每个引擎暴露的参数集不同，界面随之不同）
- 参考音频上传（**质检诊断**：信噪比 / 单说话人 / 削波 / 静音段 + 修复建议）
- 生成按钮 + 队列状态
- 结果播放器：波形、A/B **盲听对比模式**、打分
- 实时日志抽屉（WebSocket 推送）

### 引擎
- 引擎卡片：安装入口、安装进度（分步）、已装/未装、能力徽标
- **能力矩阵**（issue #16 的评测证据，逐格带验证等级）
- 引擎开关与**降级顺序**
- **本地模型管理**：本地权重目录、磁盘占用、卸载
- **下载源**（首选源 + 兜底链，显示本次实际生效源 —— ADR-0016）
- 每个引擎自己的**引擎配置**（密钥、区域与 base URL、量化档等，字段由引擎声明）

### 音色库
- 音色卡片（头像 + 说明 + 试听样本）
- 卡片展开：**该音色在各引擎上的绑定列表**与健康状态
- 音色设计入口（文字描述 → 音色）
- 音色包导出 / 导入

### 历史
- 列表（搜索 / 筛选 / 分页）+ 成本与耗时统计
- 详情（参数 + 日志 + 产物）
- **重跑**：跨区跳转到「生成」区并预填充（分区后必须改为显式跳转动作，不能依赖同一滚动容器）

### 设置
- API Key（系统钥匙串）
- **转写提供方**（本地工具安装状态 + 云端提供方）
- 存储位置、**整库备份 / 恢复**
- 主题、语言
- 合规：声音授权确认、AI 生成内容标记

**跨引擎通用的配置留在「设置」，引擎特有的配置放「引擎」**——同一个开关不得出现在两处（例如下载源只在「引擎」区）。

| 风险 | 缓解 |
|---|---|
| **国内首次安装失败**（全行业最大失败源，ComfyUI 官方劝退国内用户） | 下载源走 ModelScope / 自建 CDN；**不依赖 hf-mirror 单一路径**（它对境外出口 IP 会 308 跳回真站，见 CORRECTIONS C-001）；半成品环境清理；**在干净 Windows + 干净 macOS 上做装机验收** |

## 9. 未决事项

1. **Windows 侧重型引擎** —— **已定 IndexTTS-2.5**（见 §5）。选它的决定性理由不是榜单分数，而是它是**唯一把「uv + Windows CUDA」当一等需求**的候选：仓库自带 `uv.lock`、为 win32 单独写了依赖分支绕开 `WeTextProcessing`、用 `[tool.uv.extra-build-dependencies]` 让 flash-attn 取预编译 wheel、**基础依赖里没有 fairseq / DeepSpeed / flash-attn / pynini**。
   被排除的直接原因：MegaTTS3 与 dots.tts 依赖 `pynini`（**PyPI 上 146 个平台 wheel 全是 manylinux，win_amd64 = 0**）→ `uv pip install` 解析期即失败；GPT-SoVITS 许可最干净（MIT）但 `pyopenjtalk` / `jieba_fast` 无 wheel，需用户装 MSVC。
   **v1.1 效果档候选**：VoxCPM2（Apache-2.0）；观察名单 LongCat-AudioDiT（MIT、依赖树最干净、中文 SIM 81.8 最高，但必须提供参考文本转写且项目太年轻）。
2. 盲听对比界面的具体形态（评分粒度、对比数量上限）。
3. 偏好画像的具体维度（按语种？按文本类型？按长度？）
4. **真机 3090 实测**：报告里所有 3090 数字都是推算（3090 带宽 936 vs 4090 1008 GB/s），**不得当结论引用**；IndexTTS-**2.5 自身**的 seed-tts-eval 数字官方未公布（表中 1.03/76.5 是 2.0 的）。

5. **存储层** → **已定：改用 SQLite + 一次性迁移 + 一致性快照备份，见 ADR-0017。** 原判断理由保留备查：现状是 5 个手写 JSON 索引，每个都自己实现 `_load`/`_save`/锁；由此派生出一整类缺陷（每次写入全量排序重写 → 200 段任务约 400 次全量重写；记录按引用存入、日志在 executor 线程无锁 append → 落盘日志可能被截断；写临时文件无 fsync 且解析失败被当作空库 → 静默丢库）。**这是 §2/§4/§6 多项发现共同的根因。**
6. **参数界面的分层边界** → **已定：规范层 + 位置固定、默认折叠的引擎专属层；「不支持」必须是数据，见 ADR-0018。** 调研证据保留备查：
   - **IndexTTS 的 `duration_factor` 是时长倍率，与所有引擎的 speed 相反** —— 共用滑块会让"更快"变成更慢，必须取倒数。
   - **`repetition_penalty` 在 IndexTTS 是 10.0、在 mlx-audio 是 1.05** —— 共用一个滑块就是 bug。
   - **「音高」有四种互不兼容的单位**：MiniMax `voice_setting.pitch` 半音 [-12,12]、MiniMax `voice_modify.pitch` [-100,100]、DashScope `pitch_rate` 是**比值** [0.5,2.0]、FireRedTTS3 是 `shift the pitch by N step(s)`。**MiniMax 一个请求体里就有两个不同单位的 `pitch`。**
   - **情感枚举两两不同**：MiniMax 9 值（缺 `melancholic`、多 `fluent`/`whisper`）、dots.tts 8 值带 level 1–3、IndexTTS 是 8 维向量 + alpha + 独立的音频/文本提示。**不得共用一个枚举。**
   - **六个引擎合计 30+ 个参数是条件性或无条件失效的** —— 典型两例：mlx-audio 的 `speed` 被接受、被打印、**从不使用**（而我们正在用它）；FireRedTTS3 的 `max_text_len` 声明了但正文从不引用。
   - **语种方案有六套且一套都没有**：MiniMax 41 值、DashScope 合成 11 值（`Auto`+10，**无方言成员**）、DashScope 登记/设计 10 个小写码（无 `Auto`）、mlx-audio 11 个小写+`auto`、IndexTTS 5 个、dots.tts `[CODE]` 约 110+6、FireRedTTS3 `<|Tag|>` 24+21，而 VoxCPM2 **根本没有这个参数**。
7. **FireRedTTS3 的 PoC 结论**：限定在本机 M5 Pro + torch/MPS + 仅 Base 复刻，须回答 MPS RTF、17 项回归集表现、以及剥离 `flash_attn`/`fasttext` 后是否仍可用。过了才采纳。→ **已跑通（2026-09-20）：补丁后 20/20 全过，fp32 RTF 中位 2.22、MPS 峰值 11.7 GB；采纳与否待人工听感判定**，证据见 `docs/evaluation/2026-09-20_FireRedTTS3_PoC.md` 与 `scripts/fireredtts3_poc/`。
8. **MiniMax 待办与待核**：异步接口的 payload **键名与同步不同**（`audio_sample_rate` 而非 `sample_rate`、`english_normalization` 而非 `text_normalization`；没有 `force_cbr` / `timbre_weights` / `subtitle_*` / `output_format` / `stream`；`opus` 只接受 8/12/16/24/48k，否则**任务失败**）——因为长文本要走异步，这条必须单独构造 payload 而不能复用同步的。待核：单把 API key 能否跨 `.io`/`.cn` 两区（官方未说明）；异步接口是否支持复刻音色、返回格式是否为可用 WAV。另已确认：**复刻需要账号实名/付费档**（错误码 `2038` = 无复刻权限），且**音色设计拒绝模仿真实人物**。
9. **本地转写工具的云端提供方**：决策 #15 的云端那半需要一个真实提供方，而当前唯一可选项是测试替身。**在补上真实提供方之前，测试替身必须先下线**（它会往音色库写入写死的测试文本，再被 `requires_reference_text` 的引擎当作参考文本使用，静默劣化复刻）。

## 10. 建议的下一步

不要先写 UI。按证据显示的风险排序，先做三件低成本验证：

1. **装机路径实测**：干净 Windows（无 Python）+ 干净 macOS，各跑一遍「下 uv → 装 PBS → 建 venv → 装 torch/MLX → 下模型 → 出第一段音频」，记录全部失败点。**这份记录就是第一版安装器需求文档。**
2. **引擎能力矩阵实测**：5 个引擎各跑中文回归集（数字/日期/金额/中英混读 + 多音字），产出**你自己的引擎能力矩阵**——这是产品的核心资产，且无法从任何榜单抄到。
3. **中文听感 A/B**：Qwen3-TTS 本地 vs 阿里 vs MiniMax vs Fish Audio，同一音色同一文本，人工盲听。这是唯一能验证 §5 那张表的方式。
