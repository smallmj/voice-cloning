## 0. 执行摘要

1. **赛道已经有两个 3 万+ star 的「成品级」对手，且做的东西和你高度重叠。**
   - **jamiepine/voicebox** ★52,237（MIT）——Tauri + FastAPI，7 引擎统一前端，本地优先，含音色档案、生成版本/重跑、异步队列、模型管理。**这是目前最接近你目标形态的对手。**
   - **debpalash/VoiceStudio**（原 OmniVoice-Studio）★31,222（AGPL-3.0）——Tauri v2 + FastAPI，16 个 TTS 引擎 + 11 个 ASR 引擎，模型目录、GPU 自动检测、诊断包、MCP、批量队列。**最完整的「本地 ElevenLabs 替代」。**
   - 另有 **rsxdalv/TTS-WebUI** ★3,264（MIT，Gradio+React，20+ 模型全插件化）、**ComfyUI Desktop**、**Stability Matrix**、**LM Studio**、**Pinokio** 作为环境/模型管理范式。
2. **但「四件事」里没有一家全做完**——多引擎统一抽象已有较好实践；模型安装体验是**全行业最大的失败源**；历史记录与重跑只有 2–3 家做好；**音色预设的「跨引擎可移植」是明确的空白**（详见 §A.3）。
3. **桌面技术栈：首选 Electron + React + Python sidecar，不是 Tauri。** 决定性理由不是体积（你模型本身就 GB 级），而是 **wavesurfer.js/peaks.js 的音频波形生态** + **ComfyUI Desktop 的 Electron+uv+Python 量产参考实现** + 签名/自动更新工具链最成熟。Tauri 2 的「小 30 倍」在离线分发时要吐回 127–180 MB WebView2。
4. **本地运行时：唯一现实路线是「自带 uv 二进制 + uv 托管 Python(python-build-standalone) + 每实例独立 venv + 运行时 `uv pip install torch`」。** 没有任何打包器能把 torch 干净冻成单文件（PyInstaller 打 torch ≈4GB 且跨机 DLL 报错；pex 实测失败；Nuitka 触发 anti-bloat）。**黄金参考实现是 ComfyUI Desktop 的 `src/virtualEnvironment.ts`。**
5. **国内首次安装是最大单点风险，且必须在架构层解决**：ComfyUI 官方 discussion #390 直接建议国内用户**别用 Desktop 改用整合包**；uv 下载 PBS Python 会失败（issue #1345）；HF 的 Xet 传输让 `HF_ENDPOINT` 镜像失效（huggingface_hub #4475）。→ **国内默认 ModelScope + 预打包离线运行时不是可选项，是主路径。**
6. **macOS 上 TTS 是二等公民，且这是模型层问题不是打包问题**：GPT-SoVITS 维护者明确建议 Mac 用 CPU（MPS 有内存泄漏 + 音质差）；`PYTORCH_ENABLE_MPS_FALLBACK=1` 救不了 TTS 最关键的 `nn.Conv1d`（`Output channels > 65536 not supported at the MPS device`）。→ **产品必须在架构上承认「Mac 上强引擎少」，并做按平台自动选引擎。**

### 结论

- **多引擎统一抽象**：已有 2 家做到「能用」（voicebox、VoiceStudio），但**没有人做到「语义统一」**——同一段文本在 A 引擎的 `[laugh]` 会被朗读、在 B 引擎才会表演；同一份参考音频在 A 引擎保得住说话人、在 B 引擎保不住。**「引擎能力中立层」是真空**。
- **模型安装体验**：整体是**全行业最弱的一环**，连 ComfyUI Desktop 这种顶级团队都在 issue 里翻车（半成品 venv 死循环、国内 uv 下载失败、0xC0000005）。**这是你最容易建立口碑差异的地方**，但也最容易翻车。
- **历史记录与重跑**：只有 voicebox 做到了「生成版本 + 血缘 + 重跑」，VoiceStudio 和 TTS_MultiModel 到了及格线，**其余基本没有**。绝大多数用户现状是「生成完关掉页面，想重来只能重新输入」。
- **音色预设管理**：最好的两家只做到「本 App 内的档案 + 导入导出」。**没有任何一家解决「跨引擎的音色身份」**——换引擎就要重新录参考音频，微调过的 LoRA 也无法跨引擎复用。

| **2** | **引擎能力中立层 + 降级路由** | 只有 VoiceStudio 做到了「不支持的引擎拒绝任务」；voicebox 把副语言标签当成普通文字读出来（抽象泄漏） | ⭐⭐⭐⭐⭐ 定义一套能力声明（语种/克隆/指令/情感/平台/显存/许可证），UI 据此**禁用或自动降级**，而不是让用户撞墙 |
| **3** | **首次安装的可靠性（尤其国内）** | ComfyUI issue #1345/#1558/#1574/#1611；官方 discussion #390 直接劝国内用户别用 Desktop | ⭐⭐⭐⭐⭐ 官方自己都放弃了。做「离线运行时 + 国内镜像 + 失败可恢复（不留半成品 venv）」就是降维打击 |
| **4** | **生成版本血缘 + 重跑 + 对比** | 只有 voicebox 做了。用户实际痛点：想换引擎重跑同一段、想比较 A/B 引擎、想微调参数后对比 | ⭐⭐⭐⭐ 实现成本不高（一次生成 = 一条带参数的记录），体验差异巨大 |
| **5** | **GPU/显存感知的「先诊断再开工」** | 各家都是**跑到一半 OOM 才报错**；IndexTTS #411 用户反馈「OOM 后显存没清空，只能重启」 | ⭐⭐⭐⭐ 启动时探测 GPU 型号/驱动/可用显存/磁盘，直接给「推荐引擎 + 预计耗时 + 降级选项」 |
| **6** | **macOS 的一等公民体验** | GPT-SoVITS 官方建议 Mac 用 CPU；IndexTTS MPS 报 `65536 not supported`；AllTalk Mac「理论上的，未测试」；VoiceStudio **Intel Mac 完全不能跑**；只有 voicebox 认真做了 MLX | ⭐⭐⭐⭐ macOS 上「强的引擎」和 Windows 不同。做**按平台自动选引擎 + 明确标注平台能力**，可以吃下整个 Mac 创作者市场 |
| **7** | **许可证护栏** | 只有 VoiceStudio 有 per-engine 许可证表、voice-dubbing-runtime 有 license gates | ⭐⭐⭐ 面向创作者/商业客户时，「这个引擎能不能商用」是真实决策点。做成 UI 内提示成本低、信任收益高 |
| **8** | **音色设计的「可复现」** | Voice Design 在 voicebox 还是 Roadmap；TTS_MultiModel 有实现但项目刚起步（★10） | ⭐⭐⭐ 「文字描述生成音色」+「同描述可复现同音色」+「音色可保存复用」是差异化，但要依赖上游模型能力 |
| **9** | **批量与长文的稳定体验** | voicebox 有 auto-chunking + crossfade；VoiceStudio 有批量队列 + 监听文件夹；单模型 WebUI 基本没有 | ⭐⭐⭐ 有声书/播客是真实高价值场景，技术上就是分句+拼接+失败重试 |
| **10** | **首次启动的「零下载」选项** | ComfyUI Desktop 每实例 4.85 GB 且首启要下环境；voicebox 首启要下模型 | ⭐⭐⭐ 国内场景下「预打包离线包」是主路径，不是可选项 |

### 反向提醒：这些看起来是空白、其实是「已经被验证为死路」

- **「做一个统一 TTS 前端」本身不稀缺**——TTS-WebUI（★3.3k）+ voicebox（★52k）+ VoiceStudio（★31k）+ 各种单模型 WebUI 已经铺满。**你的差异化必须在「抽象质量 + 装机可靠性 + 工作流」上，而不是「支持了 N 个引擎」。**
- **不要靠「开源」当卖点**——这个赛道从 MIT 到 AGPL 的免费实现已经过剩（voicebox 还是 MIT）。**付费点只能是：装机省心、工作流效率、商业授权、团队协作。**
- **注意剪映/ ChatCut 这类「剪辑软件内嵌」的竞争**——用户要的往往不是「TTS 软件」，是「口播视频能出片」。桌面独立 App 的对手可能不是别的 TTS 客户端，而是剪映的一个标签页。

## B.2 Tauri 2 成熟度与已知坑（重点）

**时间线**：Tauri 2.0 正式版 **2024-10-02** 发布（[官方博客](https://v2.tauri.app/blog/tauri-20/)、[Release tauri-v2.0.0](https://github.com/tauri-apps/tauri/releases/tag/tauri-v2.0.0)）→ **距调研日已近 2 年，不算新框架**。2.0 实质变更：allowlist → capabilities/permissions；IPC 支持 Raw Payload；支持 iOS/Android；做了外部安全审计。生态规模：2.0 发布时关闭约 4,878 PR / 3,570 issue，Discord 约 17,700 成员——**与 Electron 的社区知识存量仍差一个量级**。

**① WebView 分裂是最大的架构性风险。** Tauri 不打包引擎：Windows=WebView2(Chromium)、macOS=WKWebView(WebKit)、Linux=WebKitGTK。官方明确 *"unsupported macOS versions do not receive WebKit updates"*——**旧版 macOS 用户会拿到旧 WebKit 内核，而 Web Audio / AudioWorklet / MediaRecorder 的成熟度随 Safari 版本显著变化**。对一个音频应用，这是实打实的风险。

**② 具体已知缺陷（可溯源）**：

| Issue | 日期 | 问题 |
|---|---|---|
| [#14263](https://github.com/tauri-apps/tauri/issues/14263) | 2025-10-08 | **弹窗被无差别拦截，阻断 Google/Apple OAuth 登录流** |
| [#13926](https://github.com/tauri-apps/tauri/issues/13926) | 2025-07-30 | Windows 管理员权限 + Administrator Protection 时 WebView2 无法启动 |
| [#9514](https://github.com/tauri-apps/tauri/issues/9514) | 2024-04-19 | **macOS 无法播放 .webm 音频**（"operation is not supported"） |
| [#9573](https://github.com/tauri-apps/tauri/issues/9573) | 2024-04-25 | **无法播放 audio blob**（NotSupportedError），同代码在浏览器正常 |
| [#14614](https://github.com/tauri-apps/tauri/issues/14614) | 2025-12-06 | 2.5 → 2.6+ 升级后 Windows 上挂起（priority 1 high） |
| [#13141](https://github.com/tauri-apps/tauri/issues/13141) | 未核实 | 部分 Intel Mac 上 webview 环境异常 |

> **#9514 和 #9573 对你是直接威胁**：音频 blob 播放正是 TTS 应用的核心路径（生成 → 播放 → 试听）。若选 Tauri，**必须先用目标 WebView 版本实测 blob/Web Audio 路径**。

**③ Linux 图形问题严重**（虽超出你 macOS+Windows 范围，但影响开发者本机调试）：白屏、resize 崩溃、`AcceleratedSurfaceDMABuf` 报错、Wayland `Error 71`；官方给了 4 级 workaround（[官方 Linux Graphics Issues](https://v2.tauri.app/develop/debug/linux-graphics/)，原始报告 [#9394](https://github.com/tauri-apps/tauri/issues/9394)）。

**④ 社区主要抱怨点**：权限模型从 allowlist 换成 capabilities 后更细粒度但**迁移成本高、文档与示例不足**。HN 用户 KronisLV 原话：*"最大的障碍就是文档和示例，因为大家都用 Electron，那边的集体知识最多。"*

**⑤ 反向证据（对 Tauri 有利）**：
- **Jan 已成功从 Electron 迁到 Tauri 2**（`tauri.conf.json` schema = `config/2`，`macOSPrivateApi: true`，多窗口 + MLX 集成）。
- **voicebox（★52k）和 VoiceStudio（★31k）都用 Tauri 2 上线了量产产品**，且都带 Python sidecar。这说明**Tauri 2 + Python sidecar 是走得通的**。
- **但 VoiceStudio 正在从 Tauri 重写到 Electron**（README 顶部原文），值得直接去它的 issue/discussion 里挖原因。

## B.3 Electron 体积/内存实测数据

- **磁盘**：空壳 Release Win x64 ≈384 MB、macOS arm64 ≈319 MB；Hopp 单测 244 MiB。Electron 核心维护者 Felix Rieseberg 直言 *"大多数 Electron 应用落在 100 到 300 MB"*。
- **内存**：单窗口 Release macOS arm64 Electron ≈121 MB vs Tauri ≈86 MB；**Windows x64 Electron ≈93 MB vs Tauri ≈154 MB——Electron 更省**。多窗口（6 窗口）逆转：Electron ≈409 MB vs Tauri ≈172 MB。
- **内存是真实痛点**：Cherry Studio（Electron 44）有 issue 标题即「consumes too much memory」+ 另一 issue 记录 renderer 进程多次 OOM 与内存泄漏；LM Studio 有 log 目录涨到 ~8.22 GB 触发 V8 heap OOM 的崩溃单。
- ⚠️ **不可信来源提醒**：流传的「Electron 187 MB vs Tauri 14.2 MB」出自 johal.in 一类站点，同批文章含「Flutter 4.0」这类不存在的版本号，**本报告不采信**。
- ⚠️ **基准可信度警告**：Elanis 基准跑在 GitHub CI 上，Tauri Linux 启动显示 ≈30 s，HN 上被质疑「数量级错误」。**只能同平台横向比较，不能当绝对性能指标。**

## B.5 推荐

### 首选：**Electron + React + Python sidecar（uv 管 venv）**

理由（按权重）：
1. **音频/波形生态碾压对手**——wavesurfer.js + BBC peaks.js + Web Audio（AudioWorklet/AnalyserNode）开箱即用。**这是你这个产品的核心功能面，不是锦上添花。** PySide6/Flutter/Avalonia 都得自己拼。
2. **Python 集成有可抄的量产实现**——ComfyUI Desktop 的 `src/virtualEnvironment.ts`（uv 管 venv + node-pty 转发输出）是公开源码的同构参考。
3. **体积优势在 Tauri 侧不成立**——你模型 GB 级，Electron 那 200–300 MB 是噪声；而 Tauri 若为离线分发打 WebView2 fixedVersion 要吐回 180 MB。
4. **单窗口内存 Electron 在 Windows 实测更省**（93 MB vs 154 MB），冷启动也更快（206 ms vs 711 ms）。
5. **签名公证 + 自动更新工具链最成熟**（@electron/notarize + electron-builder + electron-updater）。
6. **踩坑资料与人才池密度最优**。

**风险与对策**：
- 渲染进程内存泄漏是真实事故源（Cherry Studio 有 OOM issue）→ **把「长时运行内存基线 + 自动化泄漏检测」写进立项验收标准**。
- 多窗口内存线性增长 → **主窗口内用路由，不要多开窗口**。
- 二进制体积大 → 接受；用**安装时下载模型**而非打包模型。

### 备选 A：**Tauri 2 + React + Python sidecar**

**只在满足其一才值得换**：① 要发一个**不含模型**的轻量云推理版（3–5 MB 壳是真优势）；② 明确要延伸到 iOS/Android；③ 团队已有 Rust 能力。

**必须先在目标版本上验证的三件事**（否则不要选）：
1. **音频 blob 播放**（issue #9573）与 **macOS .webm 音频**（#9514）在你的目标 WKWebView 版本上是否正常——**这是 TTS 应用的核心路径**。
2. **弹窗/OAuth 是否仍被拦截**（#14263）——若接第三方登录会直接卡死。
3. **macOS 最低支持版本**——WKWebView 内核随系统版本走，对 Web Audio 是硬约束。

**加分事实**：voicebox（★52k）和 VoiceStudio（★31k）都用 Tauri 2 + Python sidecar 上线了产品，说明这条路走得通；**但 VoiceStudio 正在重写到 Electron**，建议直接去挖原因。

### 备选 B：**PySide6**

**唯一无 IPC 方案**（同进程 `import torch`），PyInstaller `--onedir` 实测 ≈118 MB。

**风险**：
- **Qt for Python 是 LGPLv3/GPLv3 或商业版**——闭源商业分发需满足动态链接 + 可替换义务，或购买商业许可。**这是成本项，不是免费的。**
- 波形/动效生态远弱于 Web。
- **但**：`akita141188/voice-dubbing-runtime`（Apache-2.0）、`ViacheslavChernyshov/YouTube-Dubbing-Studio`、`begin0808/VoxCPM2`、fish-speech 的官方 PyQt6 界面都在用——**证明这个品类有人用 Qt 做出来了**。

### 不推荐

- **Flutter Desktop**：桌面音频插件参差、无决定性优势、要引入 Dart。
- **.NET MAUI**：Linux 尚不支持，桌面打磨弱于 Avalonia。
- **Avalonia 可作第三备选**（Stability Matrix 已量产验证），代价是你会同时维护 C# 和 Python 两套非前端语言。

# C. 本地模型运行时管理

> 完整版（含约 200 条来源）见 `research-本地Python推理环境与运行时管理.md`。以下为结论与可执行清单。

## C.1 嵌入式 Python 打包

**结论：uv + python-build-standalone(PBS) 是唯一现实路线；conda 只在必须用 conda-only 包（pynini）时才上。**

- **uv 可行且成熟**：`uv python install 3.12` 装到 `~/.local/share/uv/python/`，不污染系统 Python。版本节奏：0.9.0 (2025-10-07) → 0.11.0 (2026-03-23) → 0.12.9 (2026-09-01)。
- **国内可用性是软肋（有硬证据）**：ComfyUI Desktop issue #1345 的原始日志 `uv venv --python 3.12 --python-preference only-managed` → `error: Failed to download https://github.com/astral-sh/python-buil...`。解法是 `UV_PYTHON_INSTALL_MIRROR`（社区验证：`https://registry.npmmirror.com/-/binary/python-build-standalone`、`https://mirror.nju.edu.cn/github-release/astral-sh/python-build-standalone/`）+ uv.toml 的 PyPI index。
- **PBS**：2024-12-03 由 Gregory Szorc 移交 Astral；产物 `.tar.zst`，嵌入用 `install_only` 变体；**单 asset 约 23.1–41.9 MB**；macOS(aarch64/x86_64) 与 Windows x86_64 均有产物。
- **conda 路线**：conda-pack / constructor / **pixi + pixi-pack**（Rust 写、带 lockfile）都可行。**唯一必须走 conda 的现实场景是 conda-only 包——典型是 CosyVoice 依赖链里的 pynini（pip 编译在 Win/Linux 失败）。**
- **⭐关键洞察**：**LLM 类产品普遍绕开 Python**（LM Studio 无 Python；Ollama/Jan/GPT4All/AnythingLLM 也都无 Python），因为它们的推理栈本身不是 Python。**而 TTS/声音复刻必须用 PyTorch，只能走「自带 uv + 托管 Python + venv + 运行时 pip install torch」。ComfyUI Desktop 是唯一公开源码、可直接抄作业的同构产品。**

**没有打包器能干净冻进 torch**（这是本报告最省时间的一条结论）：

| 工具 | 结论 |
|---|---|
| PyInstaller | ❌ torch 打进 exe 约 **4 GB**（#8551）；跨机 `from torch._C import * ImportError: DLL load failed`（#5676） |
| pex | ❌ 对 torch 实测失败（pex #2388） |
| Nuitka | ❌ torch 触发 anti-bloat 报错（#3288，2025-01-09） |
| Briefcase (BeeWare) | ⚠️ MSI 对超大文件（torch+CUDA）有已知限制（#1788） |
| shiv | ❓ PEP 441 zipapp，对含大量二进制扩展的 torch 是否可用 **未核实** |
| PyApp (ofek/pyapp) | ⚠️ 发行版来源就是 PBS，`PYAPP_DISTRIBUTION_EMBED=1` 可嵌入；适合纯 Python CLI，**不适合带 torch 的主流程** |
| uv / pixi-pack / conda-pack | ✅ 推荐 |

**→ 正确姿势：分发 Python 运行时 + venv + 运行时 pip install，不是冻单文件。**

**首次启动失败的真实故障（全部可核实）**：#1558 卡在 "Setting up Python Environment"（2026-01-23）；**#1574 半成品 `.venv` + 缺 uv 托管 Python → `uv inspect error 103`，重试也失败（死循环）**（2026-01-31）；#1611 `Python process exited with code 3221225477`(0xC0000005)；#1345 uv 下载 PBS 失败；0.7.2 装后 `Torch not compiled with CUDA enabled`。**整体失败率的量化数字官方未公布——未核实。**

## C.2 Sidecar 进程 + 本地通信

- **架构范式**：ComfyUI Desktop = Electron 多进程 + 独立 Python server 子进程，`electron-log` 双文件（主进程 `main.log` / server `comfyui_.log`），路径遵循平台标准（macOS `~/Library/Logs/{app}`、Windows `%AppData%\{app}\logs`）。**这套「双文件 + 平台标准日志目录 + 内置终端」值得照抄。**
- **通信选型**：**本地 HTTP(FastAPI+uvicorn) + WebSocket 最主流**。stdio JSON-RPC 无端口无防火墙，但无法多路复用、音频 base64 膨胀 33%、协议流与日志流混在一起。gRPC/ZeroMQ 收益不抵打包成本。
- **⭐ 必做的五个坑（都有来源）**：
  1. **端口占用** — ComfyUI 默认 127.0.0.1:8188 多开会报 `Port 8188 is already in use`。**正确做法：`listen(0, "127.0.0.1")` 让 OS 分配动态端口，再把真实端口回传前端。**
  2. **防火墙** — 绑 `127.0.0.1`（非 `0.0.0.0`）+ 动态端口能大幅降低 Windows 防火墙弹窗概率。
  3. **本地端口安全（最常被忽略）** — `127.0.0.1` 上的服务对**本机所有进程（含任意浏览器页面）**可见。**必须用主进程启动时生成的 bearer token 经环境变量注入 sidecar、前端带上。**
  4. **进程孤儿** — Node `child.kill()` 只杀直接子进程，**Windows 上孙进程会存活**；需要 Windows-aware 进程树 teardown。注意 `child.killed` 只表示信号已发送，不代表已退出。
  5. **杀软** — 未签名 PyInstaller exe 被 Defender 报毒（bootloader 自解压行为）。**代码签名 + 不用单文件 exe。**

## C.3 模型下载 / 校验 / 断点续传

- **2025-10 是分水岭**：`huggingface_hub v1.0.0`（2025-10-24）迁移到 httpx；`hf` CLI 取代 `huggingface-cli`；**全面用 `hf_xet` 传输**；**`hf_transfer` 被移除**，`HF_HUB_ENABLE_HF_TRANSFER` 变 no-op（issue #4219，2026-05-10），改用 `HF_XET_HIGH_PERFORMANCE`。`resume_download` 在 0.23.0 弃用（官方口径「默认续传」）。
- **续传的真实坑**：#3007（2025-04-15）resume 忽略 5xx、**返回不安全缓存数据**；#4196（2026-05-06）**`hf download` 中断后重跑从头开始**；PR #4143（2026-04-24）「Harden resume validation」加 `.incomplete` resume 元数据 + `If-Range`/`Content-Range` 校验 → **应锁到含此修改之后的版本（具体版本号未核实）**。
- **⭐ 国内镜像的硬结论**：`HF_ENDPOINT=https://hf-mirror.com` 是标准做法，**但 Xet 流量走 `cas-server.xethub.hf.co`，`HF_ENDPOINT` 覆盖不到（huggingface_hub #4475）**，必须 `HF_HUB_DISABLE_XET=1`——**而 hf-mirror 用户报告该变量「好像不生效」（hf-mirror-site #64，日期未核实）**。
  → **国内分发的下载层必须自研，不能假设官方客户端的镜像/关闭开关一定生效。国内默认走 ModelScope。**
- **可复用组件**：`aria2`（`-x 16 -s 16` 多连接分块 + session 续传，内存 4–9 MiB）、ModelScope CLI（`modelscope download --model ... --include/--exclude`）、`hfd.sh` 等社区 HF+aria2 脚本。
- **自建清单**：下载前查磁盘余量 → 下载后按固定 SHA256 清单校验 → 失败可恢复的下载队列。

## C.4 Apple Silicon 上跑 PyTorch TTS（结论：Mac 是二等公民）

- **MPS 缺口的官方入口**：coverage tracking pytorch#141287（2.6+，2024-11-21）、Most requested ops #154052（2025-05-21）。
- **`PYTORCH_ENABLE_MPS_FALLBACK=1` 不是万能**：pytorch#134416 显示 `nn.Conv1d` 仍抛 **`Output channels > 65536 not supported at the MPS device`**——**而这恰好是 TTS 最核心的算子**（coqui-ai-TTS #248、coqui/TTS #4124）。XTTS v2 在 MPS 上直接 hang（coqui/TTS #3649，M1 Max 64GB 也不动）。
- **各项目 Mac 状态**：
  - **GPT-SoVITS**：官方建议 Mac 用 **CPU**（维护者口径：MPS 有内存泄漏 + MPS 训练音质差，issue #808）；install.sh 支持 `--device MPS|CPU`；社区有 CPU 专用分支。
  - **IndexTTS/2**：MPS 报同类错误（#351、#193 "65536 not supported"，M3 Max）；官方 README 明确**「仅支持 uv，conda/pip 可能导致依赖不正确」**。
  - **CosyVoice**：依赖 pynini，官方要求 conda；社区有 MPS fork。
  - **Fish Speech**：#789 MPS dtype mismatch → #790 修了 dtype 但 API 仍 500。
- **CUDA-only 依赖在 macOS 上必然安装失败**：fairseq（M1 装不上）、fairseq2、DeepSpeed（只有 python-only 预览分支能绕开）、flash-attn（不支持 Apple silicon）。
  → **安装器必须按平台把 deepspeed / flash-attn / fairseq 从依赖里剔除，否则 macOS 上 pip 解析阶段就炸。**
- **RTF 量级参考**（不同项目自测，模型不同不可横比）：Kokoro 82M RTF ≈0.03 / <1GB；XTTS v2 RTF ≈0.18 / ~4GB；qwen3-tts 0.6B bf16 在 M1 8核16GB 上 RTF ≈1.3–1.7（慢于实时），int8 <1.0；Metal 后端起效后 0.6B 在 M1 RTF 1.5→0.60、M2 Pro 0.36。

## C.5 显存/内存不足的降级策略

- **策略（按性价比）**：fp16/bf16 → int8/AWQ-int4 → accelerate `cpu_offload`/`device_map` → 分块/降 batch/关 KV cache/懒加载 → 卸载到磁盘（**桌面端成熟实现未核实**）。
  - 量化代价明确：CosyVoice3 实测 FP32 2.3GB → FP16 1.1GB → INT8 0.6GB → AWQ-INT4 0.3GB，但 **MOS 4.2→3.5**。
- **显存估算**（来源实测/官方）：Kokoro <1GB；XTTS v2 ~4GB；GPT-SoVITS 官方「≥6GB」；CosyVoice3「峰值轻松破 6GB，低于 8GB 几乎无法稳定运行」；IndexTTS2 有 3060 12G 用户反馈「15 秒音频需 30 多秒推理」。
  → **桌面端最低门槛建议定 6–8GB 显存；4GB 卡只适合 Kokoro 这类小模型。**
- **检测**：NVIDIA 用 `nvidia-smi` / `torch.cuda.mem_get_info()` / **`pynvml`（nvidia-ml-py3，比包 nvidia-smi 快得多，PyTorch 官方文档建议用它采集 PyTorch 之外的分配量对账）**；Apple 用 `torch.mps.recommended_max_memory()`。
- **产品化**：**启动前**探测显存总量 vs 模型需求 → 不够就给「切 int8 / 切 CPU / 换小模型」三选项，**而不是等 OOM**。
- **必须做进程隔离**：IndexTTS #411 用户反馈「显存不足报 OOM 后没有清空，只能重启」——**这是「sidecar 必须可整体重启」的硬理由。**

## C.6 Windows 上的 CUDA / cuDNN / VC++ 运行时分发

- **不需要用户装 CUDA Toolkit。** PyTorch 官方原文：*"The PyTorch pip wheels and conda binaries ship with all needed CUDA dependencies and thus no locally installed CUDA toolkit is needed and used unless you build PyTorch from source or custom CUDA extensions."*
- **要检查的是驱动版本**：CUDA 11 起有 Minor Version Compatibility；**CUDA 12.x 的 Windows 最低驱动 >=525**。→ **安装向导检查「驱动版本」而不是「有没有装 CUDA Toolkit」。**
- **torch wheel 与 CUDA 对应（2025→2026 变动剧烈）**：2.10 支持 CUDA 12.6/12.8/13.0；**2.11 起 CUDA 13 成为默认**；2.14 为 12.6/13.0/13.2，安装命令 `pip3 install torch --index-url https://download.pytorch.org/whl/cu130`。
  → **不要写死 cu121**。ComfyUI 官方就是双包策略：**新包 py3.13 + cuda13.0 / 老卡包 py3.12 + cu126**。
- **常见坑（每条有来源）**：
  - **pip 装成 CPU 版 torch**：PyPI 不托管 CUDA 构建，裸 `pip install torch` 会装 CPU-only（pytorch#168065）。真实翻车案例：ComfyUI Desktop 0.7.2 + CUDA 13.0 → `AssertionError: Torch not compiled with CUDA enabled`。
  - **VC++ Redistributable**：PyTorch Windows 官方文档原文 *"since we didn't pack some libraries and VS2017 redistributable files in, please make sure you install them manually"*；报错文案 `Microsoft Visual C++ Redistributable is not installed, this may lead to the DLL load failure`（pytorch#126507）。→ **安装器静默检测并装 vc_redist.x64.exe。**
  - **中文路径**：`torch.save` 中文文件名乱码（pytorch#98918、#90040）。→ **默认目录一律 ASCII。**
  - **杀软拦截**：未签名 PyInstaller onefile 被 Defender 报毒。→ 代码签名 + 不用单文件。

## C.7 国内首次安装体验优化（ComfyUI 官方做法可直接抄）

- 设置里提供「**Python 安装镜像**」：托管 Python 来自 astral PBS，URL 替换默认 GitHub 地址，**支持 `file://` 从本地目录读取发行包**，并自动检查镜像可达性。
- 「**PyPI 镜像 URL**」（示例 `https://mirrors.aliyun.com/pypi/simple/`）+「使用中国镜像」总开关。
- 官方 discussion #390 对国内用户的建议是改用 portable/整合包 → **反过来说「离线/预打包运行时」在国内不是可选项，是主路径。**
- 其他可组合：`UV_PYTHON_INSTALL_MIRROR`、uv.toml 默认 index、`HF_HUB_DISABLE_XET=1` + `HF_ENDPOINT=hf-mirror.com`、ModelScope 备选源、aria2 分块续传。

## D.2 相对竞品的三个差异化支点

结合 §A.4，建议把资源集中在**这三点**（而不是「支持更多引擎」）：

1. **装机可靠性作为一等公民**——离线/镜像运行时、失败可恢复（绝不留半成品 venv）、可视化诊断、一键导出诊断包。这个赛道的所有对手都在这里翻车（连 ComfyUI 官方都劝退国内用户）。**这是最容易建立口碑、也最容易被忽视的地方。**
2. **跨引擎统一音色资产 + 能力中立层**——定义一个「音色」对象（参考音频 + 转写 + 引擎特定适配器 + 可选的 LoRA），以及一套引擎能力声明（语种/克隆/指令/情感/平台/显存/许可证）。**没有任何对手做到。** 配套做「生成版本血缘 + A/B 对比 + 重跑」。
3. **macOS 一等公民**——按平台自动选引擎（macOS 上优先 MLX/小模型，Windows 上优先 CUDA 大模型），UI 明确标注每引擎的平台能力。**VoiceStudio 直接放弃了 Intel Mac；GPT-SoVITS 官方让 Mac 用 CPU。** 这是被放弃的市场。

## D.3 立项前必须做的三个验证（低成本、高信息量）

1. **音频路径验证**（如果倾向 Tauri）：在目标 WKWebView 版本上实测 **audio blob 播放**（issue #9573）与 **.webm 音频**（#9514）。失败就直接排除 Tauri。
2. **装机路径验证**：在干净的 Windows（无 Python）+ 国内网络 + 干净的 macOS 上，各跑一遍「下载 uv → 装 PBS Python → 建 venv → 装 torch → 下模型 → 出第一段音频」。**把失败点全部记录**——这份记录就是你第一版安装器需求文档。
3. **引擎能力实测**：选 3 个候选引擎（建议 **IndexTTS 2.5 / Chatterbox(MIT) / Kokoro(低配兜底)**），在 macOS M 系 + Windows NVIDIA 上实测：显存占用、RTF、克隆相似度、是否支持副语言标签/指令控制。**产出你自己的引擎能力矩阵**——这将成为产品的核心资产。

## D.4 已知的、需要在本报告中保留的限制

1. **基准数据可信度**：Elanis 基准跑在 GitHub CI 上含未量化噪声（Tauri Linux 启动 ≈30 s 被质疑「数量级错误」）→ 只可同平台横向比较。
2. **PySide6 / Flutter / Avalonia 的冷启动与空窗口内存没有找到同口径公开数据，标为「未核实」。**
3. **明确排除 johal.in 系列**（出现「Flutter 4.0」等不存在的版本号），该站的 Electron/Tauri 对比数字不采信。
4. 部分商业产品定价为抓取时点值，变动频繁；ElevenLabs 是否有原生桌面 App **未找到一手证据**，按「Web/PWA + 移动 App」记录。
5. ComfyUI Desktop 首次安装的**整体失败率量化数字官方未公布——未核实**。
6. 本环境 `web_fetch` 被 DNS 策略拦截，所有页面经 `curl` 抓取；少数 JS 重度渲染页面（如 elevenlabs.io/download）返回内容为空，相关内容标为未核实。
