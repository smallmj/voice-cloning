# 设计音色的预览样本即参考音频，设计音色是一等音色

issue #11（音色设计）：用户用一段文字描述创造一个不存在的声音，无需参考音频。

**两条绑定关系（它们必须一起存在，所以是一条决定）**：
1. **设计引擎的预览样本成为该音色的参考音频**。声音设计 API 在创建音色时返回一段试听音频；它被存为该音色的 `ref.wav`（转写即试听文本）。这正是 ADR-0001「参考音频是音色的真相来源」的自然延伸：对其他只支持复刻的引擎而言，设计音色与上传参考音频创建的音色没有任何区别——同一条绑定、生成、导出、删除路径，不需要任何特判分支。不这样做的话，每个引擎的绑定逻辑都得为「没有参考音频的音色」开第二条通路，模型立刻变得脆弱。
2. **音色记录携带来源（`origin`: cloned / designed）与设计血统（engine、描述、试听文本）**。音色库必须能区分两种来源（issue #11 验收标准），且血统字段让「重新设计」「追溯这段声音是怎么来的」成为可能，而不需要用户记住任何东西。

**能力门禁不变**：只有声明 `voice_design` 能力的引擎出现在设计选项中；未声明的禁用并显示原因（复用 #9 的能力门禁，缺失声明即不支持）。设计云端引擎（qwen-voice-design → qwen3-tts-vd）的 `target_model` 与其合成 `model` 必须一致，这是厂商 API 的硬约束，引擎内固定。

**Consequence**：设计失败时临时的无参考音色记录会被立刻删除——不会留下一个永远不可用、也不能参加对比的孤儿音色。
