# 0020 — 应用在线更新：半自动引导 + 更新渠道首选/兜底 + 经代理下载必须校验

日期：2026-09 · 状态：已采纳 · 关联：issue #62、ADR-0013、ADR-0015、ADR-0016、ADR-0017

## 背景

应用此前只能手动去 GitHub Releases 下载安装包升级。国内访问 GitHub 不稳定，且用户无法确认下载回来的文件经第三方加速后是否完整。启动检测 + 应用内下载是自然需求，但"更新"有两种深度：electron-updater 式全自动静默替换，或应用内下载后引导用户完成安装。

## 决策

1. **半自动引导，不引入 electron-updater**。应用内下载（进度可见、可取消）→ 下载完 Windows 自动运行 NSIS 安装器、macOS 自动挂载 dmg 引导拖拽。理由：macOS 上全自动替换受签名/公证与 Squirrel 限制本来就做不干净，两平台行为统一为引导式；实现面小一个量级，不要求 release 带 sha512 的 electron-updater 清单体系之外的新基建。

2. **「更新渠道」与 ADR-0016 的「下载源」是两个轴，不得混用**。下载源服务模型权重（HF/ModelScope/PyPI/wheel），更新渠道服务应用安装包。渠道为三选一：**自动（默认）/ GitHub 官方 / 国内镜像**；自动 = 镜像优先、官方静默兜底；镜像前缀可编辑（默认 `https://gh-proxy.com/`）。沿用 ADR-0016 的两条铁律：**首选源 + 静默兜底链**，以及**必须显示本次实际生效渠道**。API 查询与资产下载走同一渠道规则。

3. **经第三方代理前缀下载必须做完整性校验**。release 附 electron-builder 标准清单（`latest.yml` / `latest-mac.yml`，含 sha512），下载完成后校验；清单缺失时 UI 警告但允许继续。代理前缀是公共服务、随时可换，校验是发现篡改/截断的唯一手段。

4. **只认正式 release；提醒语义带"跳过此版本"**。启动异步查询 `releases/latest`（5 秒超时静默放弃，不打扰）；弹窗可勾选跳过该 tag，此后仅当最新 tag ≠ 被跳过 tag 才再提醒，设置页手动检查不受影响。被跳过 tag 与镜像前缀同存 SQLite settings（ADR-0017）。

5. **可测逻辑收进 updater 单一模块，fetch 注入**；弹窗、进度事件、启动安装器/挂载 dmg 是 main.ts 里的副作用薄壳，不设第二条测试缝。

## 后果

- release 发布流程新增硬约定：必须附平台安装包 + 对应 latest 清单；在发布文档中写明（CI 工作流另议）。
- 仓库当前无 release，"查询失败/无可用版本"路径是上线初期的常态，必须静默处理。
- 全自动更新（静默替换、差分更新）如将来要做，届时应复评 electron-updater；本 ADR 的渠道与校验决策不受影响。
- 术语已固化进 CONTEXT.md：「更新渠道」「跳过此版本」。
