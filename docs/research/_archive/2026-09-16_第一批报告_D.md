## 1. XTTS-v2（Coqui）

### 1.1 基本信息
- **参数规模**：约 **467M**（多个来源一致：~467M / ~470M）
- **发布方**：Coqui（Coqui AI，德国）
- **最新版本与日期**：**XTTS-v2**（v2.0.2 权重）。HuggingFace 仓库 `coqui/XTTS-v2` 最后修改时间 **2023-12-11**，实际发布时间约 2023 年 9 月。这是**最后一个版本**——Coqui 公司已于 **2024 年 1 月**关停。
- **HF 数据**：下载量 7,300,281 / likes 3,806
- **代码仓库**：`coqui-ai/TTS`（🐸TTS），**46,016 stars**，最后 push **2024-08-16**，代码许可 **MPL-2.0**

### 1.2 能力
- ✅ **零样本克隆**：仅需 **6 秒**参考音频
- ✅ **跨语言克隆**（用 A 语言音色说 B 语言）
- ✅ **多说话人参考 + 说话人插值**（v2 新增）
- ✅ **情感/风格迁移**：通过「克隆参考音频的情感」间接实现，无显式情感标签
- ⚠️ **从文本描述设计音色**：❌ 不支持
- ✅ **多语言**：**17 种**——英语 en、西班牙语 es、法语 fr、德语 de、意大利语 it、葡萄牙语 pt、波兰语 pl、土耳其语 tr、俄语 ru、荷兰语 nl、捷克语 cs、阿拉伯语 ar、**中文 zh-cn**、日语 ja、匈牙利语 hu、韩语 ko、印地语 hi
- ⚠️ **流式**：支持流式推理（`inference_stream`），但非主流用法
- ⚠️ **长文本**：需自行分句切分
- ❌ **语音转换（VC）**：非主打（需额外模型）
- **中文质量**：⚠️ **可用但一般**。中文是 17 语之一，但训练数据以英语/欧洲语言为主，中文韵律和自然度明显弱于英文，且受 CPML 限制无法商用微调改进。**未核实**具体中文 CER 数字。

### 1.3 硬件
- **显存**：约 **2.5 GB VRAM**（GigaGPU 实测，2026-04-14）
- **速度**：RTF **0.38**（RTX 4060，2.6 倍实时）
- **CPU 推理**：可跑但慢，**未核实**精确 RTF
- **Apple Silicon MPS**：❌ **明确不支持 / 会挂起**。证据：
  - GitHub Issue #3649「Unable to use xtts_v2 with mps device on Apple Silicon」——M1 Max 64GB 上「it just hangs」
  - GitHub Issue #3998「mps doesn't seem to work」——直接报错
  - HF Discussion #48「support mps (torch) on mac」
- **磁盘占用**：模型权重约 2GB 级别

### 1.4 许可证 —— **CPML 1.0.0（最重要）**

**代码 vs 权重的区分（关键）：**
- **代码**（`coqui-ai/TTS` 仓库）：**MPL-2.0**
- **模型权重**（`coqui/XTTS-v2`）：**Coqui Public Model License (CPML) 1.0.0**

**CPML 原文关键条款（我直接 dereference 了 `https://huggingface.co/coqui/XTTS-v2/raw/main/LICENSE.txt`）：**

> "This license allows only non-commercial use of a machine learning model and its outputs."
> （本许可证仅允许对机器学习模型及其输出进行**非商业用途**。）

**「非商业用途」的原文定义（三条）：**
1. 个人研究、实验、测试、个人学习、私人娱乐、爱好项目、业余追求、宗教活动
2. 商业/营利实体用于**测试、评估或非商业研发**。**「使用该模型训练其他模型以供商业使用」不属于非商业用途。**
3. 任何慈善组织的慈善用途、测试或评估。**「创收活动，包括直接由政府资助的项目，不属于非商业用途。」**

**明确禁止：**
- ❌ 任何产生「直接或间接付款」的使用（模型或其输出）
- ❌ 商用训练衍生模型（→ 商用微调 XTTS-v2 也被禁）
- ❌ 再许可（sublicense）或转让许可证
- ❌ 违反后未在 30 天内整改 → 许可立即终止
- ⚠️ **专利报复条款**：若你书面主张该模型侵犯专利，你的许可立即终止

**必须履行的义务（Notices 条款）：**
> "You must ensure that anyone who gets a copy of any part of the model, or any modification of the model, or their output, from you also gets a copy of these terms or the URL for them above."
> （你必须确保任何从你处获得模型/修改版/其输出副本的人，同时获得本条款副本或上面的 URL。）

**关于「Coqui 徽标要求」的更正：**
任务描述提到 CPML「historically required the Coqui logo/attribution」。**我逐字核对了 CPML 1.0.0 全文，其中没有「必须展示 Coqui 徽标（logo）」的条款。** 存在的是上述 **Notices**（必须传递许可条款/URL）义务。徽标类要求更可能来自 Coqui Studio / Coqui API 的**服务条款**（那是云服务，非本模型权重许可）。因此「CPML 要求 Coqui 徽标」这一说法应标记为 **未核实 / 在 CPML 1.0.0 文本中不成立**。

**最致命的现实问题：**
- CPML 要求商用需**单独从 Coqui 购买商业许可**，但 **Coqui 已于 2024 年 1 月关停**，2024-01 的官方 issue #3490 中作者（erogol）称「Currently we don't have plans to change the license」。
- 2025-06 的 Discussion #4304 仍在问「现在谁能卖我商业许可」，**无官方答案**。
- 结论：**XTTS-v2 目前实际上无法获得商业授权**，对商业桌面软件 = ❌ **不可用**。

### 1.5 主观质量 / 基准
- **Artificial Analysis TTS Leaderboard**：XTTS v2 Open Weights，**Elo 920**（同一榜单 Kokoro 1,059、Higgs Audio V3 1,041）。属于 open-weights 中的中下段。
- 社区声誉：曾经是「多语言克隆质量最好」的开源模型，但**已被 Kokoro（速度/许可）、F5-TTS、CosyVoice 等超越**。目前主要价值在「17 语 + 6 秒克隆」的组合。
- **未核实**：TTS Arena 中 XTTS-v2 的具体排名与 MOS 分数。

### 1.6 工程可用性
- ✅ **官方 pip**：`pip install TTS`（`coqui-tts` 社区分支：`pip install coqui-tts`，**v0.27.5**，MPL-2.0，仓库 `idiap/coqui-ai-TTS`）
- ⚠️ **ONNX / GGUF / llama.cpp**：无官方路线
- ✅ **API 服务**：`TTS-server` 提供 FastAPI 风格 `server` 子命令
- ✅ **Gradio**：官方 HF Space 有
- **活跃度**：上游 `coqui-ai/TTS` **最后 push 2024-08-16**，实质停止维护；社区 fork `idiap/coqui-ai-TTS` 仍在更新

### 1.7 已知坑
1. **CPML 禁商用且无处购买商业许可**（Coqui 已死）—— 最硬的坑
2. **Apple Silicon MPS 直接挂起/报错**（多 issue 确认）
3. **必须提供参考音频**，且参考音频质量极大影响输出
4. **英语偏置**：非英语（尤其中文、日语、韩语）质量下降明显
5. **上游已停更**，bug 修复依赖社区 fork
6. 输出音色克隆涉及**声音权/人格权**法律风险，CPML 也不豁免这一层

## 2. StyleTTS2

### 2.1 基本信息
- **参数规模**：约 **100M**（TTS.ai 榜单标注 100M / 585h 训练数据，**未完全核实**精确参数量；其架构 = PL-BERT + Style Diffusion + ISTFTNet 声码器）
- **发布方**：Yinghao Aaron Li 等（哥伦比亚大学）
- **最新版本与日期**：**StyleTTS 2**，论文 arXiv:2306.07691（2023-06）；仓库 `yl4579/StyleTTS2` 创建 **2023-06-14**，最后 push **2024-08-10**
- **GitHub**：**6,351 stars / 705 forks**，License **MIT**（代码）
- **重要关系**：**Kokoro 就是基于 StyleTTS2 架构**（HF `base_model: yl4579/StyleTTS2-LJSpeech`）

### 2.2 能力
- ✅ **零样本说话人适配**（LibriTTS 训练版，论文称超越此前所有公开模型）
- ✅ **风格扩散**：无需参考音频即可生成合适风格（style diffusion 采样）
- ✅ **少样本微调**：官方 `train_finetune.py`，1 小时数据（~1k 样本）50 epoch，四卡 A100 约 4 小时
- ⚠️ **从文本描述设计音色**：❌ 不支持（只能采样 style 或给参考音频）
- ⚠️ **多语言**：**架构上可多语言，但官方预训练只覆盖英文**。中文需要：
  - 中文 PL-BERT（或多语言 PL-BERT `papercup-ai/multilingual-pl-bert`，支持 14 语）
  - 官方文本对齐器本身就预训练了 **英语（LibriTTS）+ 日语（JVS）+ 中文（AiShell）**
- ⚠️ **情感/韵律控制**：✅ 通过 style vector / 参考音频隐式控制，无显式标签
- ❌ **流式**：官方无；GPL 分支 `NeuralVox/StyleTTS2` 有实验性 streaming API
- ⚠️ **语音转换**：非原生支持

### 2.3 硬件
- **显存**：模型很小，推理显存需求低（**未核实**精确数字，社区普遍 2–4GB 级别可跑）
- **CPU**：README 明确提到——**旧 GPU 会出现「高音调背景噪声（high-pitched background noise）」**，解决办法是「**use more modern GPUs or do inference on CPUs**」（用更新的 GPU 或在 CPU 上推理）
- **训练**：微调需四卡 A100（1 小时数据）；从零训练 24 小时数据需 **2.5 天 × 四卡 A100**
- **Apple Silicon MPS**：❌ **不可用**。证据：Issue #114「Mac (Metal) support?」——维护者/社区回复「Same issue. It doesn't work for now.」
  - ✅ **但有 CoreML 转换路线**：`FluidInference/StyleTTS-2-coreml`（基于 LibriTTS 多说话人 checkpoint 的 Apple Silicon CoreML 转换，提供 `.mlpackage` 与 `.mlmodelc`）

### 2.4 许可证 —— MIT（代码）+ 模型额外条款
**代码：MIT License**（仓库元数据确认）

**预训练模型：附加条件（非 MIT，写在 README 的 License 节）**
> "Before using these pre-trained models, you agree to inform the listeners that the speech samples are synthesized by the pre-trained models, unless you have the permission to use the voice you synthesize. That is, you agree to only use voices whose speakers grant the permission to have their voice cloned, either directly or by license before making synthesized voices public, or you have to publicly announce that these voices are synthesized if you do not have the permission to use these voices."

**适用范围**（README 明确）：
> "Pre-trained model license: You only need to abide by the above rules if you use **the pre-trained models** and the voices are **NOT** in the training set, i.e., your reference speakers are not from any open access dataset."

即：**只有当你用预训练模型克隆「训练集之外」的真人声音时**，才必须公开声明「这是合成语音」或取得说话人许可。用公开数据集内的音色则不受此条约束。

**商用结论**：✅ 代码 MIT 可商用；✅ 自训模型无额外限制；⚠️ 用官方预训练权重克隆真人音色需履行告知义务。

**⚠️ 重要工程陷阱（README 亲口说明）**：
> "the inference depends on a GPL-licensed package, so it is not included directly in this repository."
（推理依赖一个 **GPL 许可的包**（phonemizer），因此未直接包含在仓库中。）
- 官方建议的两个替代：
  - `NeuralVox/StyleTTS2` —— **GPL 分支**，有可导入脚本 + 实验性 streaming API
  - PyPI `styletts2`（**v0.1.6，MIT**）—— 用 gruut 替代，**质量较低**（因 phonemizer 与 gruut 不匹配）

### 2.5 主观质量 / 基准
- 论文声称：在 **LJSpeech 单说话人**上「超过真人录音」，在 **VCTK 多说话人**上「与真人持平」（母语英语听者评测）
- LibriTTS 上超越此前所有公开模型的零样本适配
- TTS.ai Arena 榜单：StyleTTS 2 排第 4（票数很少，参考价值有限）
- 社区声誉：**曾被视为开源 TTS 音质天花板**，但工程化差、上手难；其架构遗产通过 **Kokoro** 发扬光大

### 2.6 工程可用性
- ⚠️ **官方 pip**：❌ 主仓库无官方 PyPI 包；社区有 `styletts2`（v0.1.6，MIT，gruut 版，质量较低）
- ❌ **ONNX / GGUF / llama.cpp**：无官方路线
- ✅ **CoreML**：`FluidInference/StyleTTS-2-coreml`
- ✅ **Gradio**：官方 HF Space `styletts2/styletts2`（社区 @fakerybakery 提供）
- ❌ **FastAPI 服务**：无官方，需自己包
- **活跃度**：最后 push **2024-08-10**，**实质停更**；118 个 open issues
- **TODO 里挂着未完成项**：README 自己写「Fix DDP (accelerator) for train_second.py — **I have tried everything I could to fix this but had no success**」

### 2.7 已知坑
1. **MPS 不可用**（需走 CoreML 转换）
2. **推理依赖 GPL 包（phonemizer）**——对闭源商业软件是法律地雷
3. **DDP 训练损坏**，官方承认修不好；只能单卡/DP
4. **NaN loss** 常见（stage 1 不能用混合精度；stage 2 batch 建议 16）
5. **OOM** 常见（SLM 对抗训练阶段；可把 `joint_epoch` 设大于 `epochs` 跳过，但质量下降）
6. **英文中心**：PL-BERT 只在英文 Wikipedia 上预训练，非英语必须自训 PL-BERT
7. **旧 GPU 高音噪声**问题
8. **项目停更**，社区支持有限

## 3. Kokoro-82M（hexgrad）

### 3.1 基本信息
- **参数规模**：**82M**（明确）
- **发布方**：`hexgrad`（社区个人/小团队）。架构来自 **StyleTTS 2**（Li et al.）；训练由 Discord 用户 `@rzvzn` 完成
- **最新版本与日期**：
  - **v1.0**：**2025-01-27**（8 语言 & 54 音色）
  - v0.19：2024-12-25（1 语言 & 10 音色）
  - HF 仓库 `hexgrad/Kokoro-82M` 最后修改 **2025-04-10**
  - **中文变体**：`hexgrad/Kokoro-82M-v1.1-zh`（Apache-2.0，新增 100 个中文说话人）
- **HF 数据**：**下载量 11,594,066 / likes 6,931**（本批次中下载量最高）
- **GitHub**：`hexgrad/kokoro`，**8,857 stars / 971 forks**，最后 push **2025-08-06**，License **Apache-2.0**

**训练成本（官方公布）**：v0.19 = 500 A100-80G 小时；v1.0 = 500 小时；**总计 1000 A100 小时 ≈ $1000**

### 3.2 能力
- ❌ **零样本克隆**：官方 v1.0 **不支持**（只有预置音色）。社区有从音频训练 voice pack 的非官方路径
- ⚠️ **少样本微调**：官方未提供训练脚本（但架构同 StyleTTS2，社区有）
- ❌ **从文本描述设计音色**：不支持
- ⚠️ **情感/韵律控制**：通过选择不同 voice tensor + `speed` 参数间接控制；**无情感标签**
- ✅ **多语言（v1.0）**：官方进阶用法列出 **8 个 lang_code**：
  - `a` 美式英语、`b` 英式英语、`e` 西班牙语、`f` 法语、`h` 印地语、`i` 意大利语、`j` 日语、`p` 巴西葡萄牙语、`z` 普通话中文
  - （model card frontmatter 只写了 `en`，但文档明确列出上述语言）
- **中文质量**：⚠️ **需要单独的 v1.1-zh 权重**。
  - 该权重「从专业数据集（龙猫数据 LongMaoData）加入 100 名中文说话人」，中文数据是**免费许可提供**的
  - ⚠️ 作者自述：「This model is **not a strict upgrade** over its predecessor since it **drops many voices**」（**丢掉了很多音色，不是严格升级**）
  - 目标只是「推进模型系列，最终恢复被丢弃的音色」——说明这是**实验性早期发布**
  - **未核实**具体中文 CER / MOS
  - 社区另有 `ardorleo/kokoro-tts-zh`（集成 103 个中文 voice，第三方）
- ⚠️ **流式**：官方 Python 包按 split_pattern 分块生成，非真流式
- ✅ **长文本**：按 `split_pattern=r'\n+'` 切分处理，可长文本
- ❌ **语音转换**：不支持

### 3.3 硬件
- **原生尺寸**：82M 参数 → fp32 约 330MB，**磁盘足迹极小**
- **CPU 推理**：✅ **非常友好**，这是 Kokoro 的核心卖点。官方定位「可以从生产环境部署到个人项目」
- **API 市场价（2025-04 官方引用）**：托管 API **$1 / 百万字符**以下（约 **$0.06 / 小时音频**）；ArtificialAnalysis/Replicate 报 65 美分/百万字符，DeepInfra 报 80 美分/百万字符
- **显存**：可忽略（社区实测可在 **3GB 显卡**甚至纯 CPU 上跑）
- **Apple Silicon**：✅ **本批次中最好的**，且有多条路线：

### 5.4 许可证 —— ⚠️ **发现许可证冲突，商用有法务风险**

**表面上**：
- `canopyai/Orpheus-TTS` 仓库的 **LICENSE 文件 = Apache License 2.0**（我确认了 raw LICENSE 内容确为 Apache 2.0）
- HF 上 `canopylabs/orpheus-3b-0.1-pretrained` 的 model card frontmatter 声明：
  ```
  license: apache-2.0
  base_model: meta-llama/Llama-3.2-3B-Instruct
  ```

**但存在公开质疑（关键）：**
- HF Discussion **#4** 标题即为：
  > **「🚨 License Conflict: Apache-2.0 License is Incompatible with LLaMA 3.2 License」**
  （2025-07-10 发起）
- **技术事实很清楚**：Orpheus 是 **Llama-3.2-3B-Instruct 的微调衍生模型**。Meta 的 **Llama 3.2 Community License** 规定：分发衍生模型时**必须** (a) 附带 Llama 许可副本、(b) 显著标注 "Built with Meta Llama 3.2"、(c) 衍生模型名称须以 "Llama" 开头、(d) 月活超 **7 亿**需另行申请许可、(e) 遵守 Meta 的 Acceptable Use Policy。
- **Apache 2.0 无法覆盖也无法免除这些 Llama 条款**。因此**单纯信 "Apache-2.0" 标签是有风险的**——实际约束应以 Llama 3.2 Community License 为准。

**商用结论**：⚠️ **不确定 / 有法务风险**。若要用，须假定 **Llama 3.2 Community License 同样适用**（含署名义务、命名前缀义务、AUP 义务）。**建议不要仅凭 "Apache 2.0" 标签就打包进商业桌面 App**——这条应标记为**需法务确认**。

**其他许可注意**：官方建议用 **Silent Cipher 给生成音频加水印**。

  3. **将 Higgs Materials 嵌入或集成到提供给第三方的产品、应用或服务中（包括 TTS、语音生成、配音或内容创作产品/服务）**
- ⚠️ **Commercial Purpose 定义极广**：包括生产使用、托管使用、任何对组织外终端用户可用的使用、任何收费/卖广告/创收的使用、超出有限评估的内部业务运营
- ⚠️ 明确禁止 **用输出训练/微调/蒸馏改进非 Boson 模型**
- ⚠️ 示例：**内部评估/基准测试/安全测试/红队** 在营利实体中**被允许**（前提：不部署到生产、不向终端用户或客户提供、不创收、不训练其他模型）
- ⚠️ 学术论文/公开 model card/非商业 demo 中的结果发布**不算** Commercial Purpose

**→ v3 商用结论**：❌ **对商业桌面软件不可用**。唯一能白嫖的是「用它做播客/视频并变现」这一创作者场景。**把它集成进 App 卖钱 = 必须向 `contact@boson.ai` 买商业许可。**

### 8.5 主观质量 / 基准（v2 官方数据）
- **EmergentTTS-Eval**：对 `gpt-4o-mini-tts` 胜率 **Emotions 75.7%** / **Questions 55.7%**
- **Seed-TTS Eval**：官方称达到 **state-of-the-art**
- **Emotional Speech Dataset (ESD)**：官方称 SOTA
- **Artificial Analysis TTS Leaderboard**：**Higgs Audio V3 TTS Open Weights，Elo 1,041**（2026 年 6 月，8 个音色）——**本批次第二高**（仅次于 Kokoro 1,059）
- 训练数据规模：**1000 万+ 小时音频数据** + 多样化文本数据，**无后训练/微调**（v2）
- 社区声誉：**表达力/情感方向的口碑很好**；但因许可（v3 转非商用）和显存门槛，工程采用受限
- **未核实** MOS

### 8.6 工程可用性
- ✅ **官方 pip**：❌ **`higgs-audio` 不在 PyPI**；从源码装：`pip install -r requirements.txt && pip install -e .`
- ✅ **Docker**：官方主推 NVIDIA 容器
- ✅ **Transformers 原生支持**：✅ `higgs_audio_v2` 已进 Transformers（有官方文档页 `docs/transformers/main/en/model_doc/higgs_audio_v2`）
- ✅ **vLLM / SGLang**：v3 推荐 **SGLang-Omni**（`sgl-omni serve --model-path bosonai/higgs-tts-3-4b --port 8000`），有 SGLang-Omni cookbook
- ✅ **托管 API**：✅ **Boson AI API**（OpenAI 兼容）
  ```bash
  curl https://api.boson.ai/v1/audio/speech \
    -H "Authorization: Bearer $BOSON_API_KEY" \
    -d '{"model": "higgs-audio-v3-tts", "input": "Hello, this is a test."}'
  ```
  免费、限速的公开预览；key 在 `boson.ai/workspace` 获取
- ❌ **ONNX**：官方无；但社区有 `onnx-community/higgs-audio-v3-tts-4b`（⚠️ 其 LICENSE 同样是 Boson 非商用协议）
- ✅ **Gradio**：HF Space `smola/higgs_audio_v2`
- **活跃度**：GitHub 仓库 8,333 stars；v3 已把文档迁到 main README，v2/v2.5 归档到 `README_V2.md`

### 8.7 已知坑
1. **v3 变成非商用许可** —— 如果你之前假设 Higgs 系可商用，这是个**重大变更**，务必核对版本
2. **v2 有 10 万 MAU 上限 + 强制署名 + 衍生模型必须叫 "Higgs Audio 2 ..."** —— 商用门槛不低
3. **v2 显存 13GB 起，官方建议 24GB**
4. **Apple Silicon MPS 支持 未核实**，官方路径全是 CUDA
5. **v3 不再依赖原仓库**，必须用 SGLang-Omni 或 Boson API —— 工程路径与 v2 完全不同
6. **禁止用输出改进其他 LLM**（v2 与 v3 都有）
7. **仓库/模型被多次重命名**（`higgs-audio-v2-generation-3B-base` → `higgs-tts-2-3b-base`；`higgs-audio-v3-tts-4b` → `higgs-tts-3-4b`），脚本/链接容易失效
8. **Llama 3 衍生的许可叠加**，合规文书工作多
9. 第三方代码风险：`boson_multimodal/audio_processing/` 目录含来自 [xcodec](https://github.com/zhenye234/xcodec) 的第三方代码，另有 LICENSE

## 10. 对「商业桌面语音复刻软件」的选型建议

**硬约束排序：许可 > Apple Silicon 可用性 > 中文质量 > 音质**

| 优先级 | 模型 | 理由 |
|---|---|---|
| 🥇 **首选** | **Kokoro-82M** | **Apache 2.0 唯一无争议**；CoreML/ANE 路线成熟（M4 25× 实时、iPhone 17× 实时、80MB）；CPU 也能跑；中文需配 v1.1-zh（实验性） |
| 🥈 **次选** | **Dia-1.6B** | **Apache 2.0 干净**；2025-12 起官方 MPS 支持（44× 于 CPU）；⚠️ **但仅英文，10GB 显存** |
| 🥉 **可考虑（评估许可）** | **Piper（老版 MIT）** | 最轻量（Pi 5 实时）；⚠️ **必须用已归档的 MIT 版或严格隔离 GPL 边界** |
| ⚠️ **需法务确认** | **Orpheus TTS** | 有 Llama 3.2 许可冲突；GGUF 可在 Apple Silicon 跑；英文 only |
| ⚠️ **需法务确认** | **Higgs Audio v2** | 可商用但有 10 万 MAU 上限 + 强制署名 + 命名约束；显存 13–24GB；MPS 未核实 |
| ❌ **不可用（商用）** | **XTTS-v2** | **CPML 禁商用，且无处购买商业许可**（Coqui 已死） |
| ❌ **不可用（商用）** | **Higgs Audio v3** | **Research & Non-Commercial 许可** |
| ⚠️ **不推荐** | **StyleTTS2** | MPS 不可用；推理依赖 GPL 包（phonemizer）；项目停更 |
| ⚠️ **不推荐** | **Sesame CSM-1B** | 仅英文；门控 + research/educational 表述；MPS 慢；16 个月无更新 |

**关于中文**：本批次**没有任何一个模型的中文能力可以称为优秀**。XTTS-v2 支持中文但质量一般且禁商用；Kokoro v1.1-zh 是实验性权重且丢了很多音色；Higgs v2 支持 zh 但显存门槛高且许可有约束；其余全部英文或中文音色极少。**如果中文质量是硬指标，本批次不足以支撑产品，需要另开批次调研 CosyVoice / F5-TTS / IndexTTS2 / Qwen3-TTS 等中文强项模型。**
