## 1. 产品定义

**一句话**：一款 macOS / Windows 桌面应用，把**云端 API** 与**本地模型**编排进同一个工作流，用同一套音色完成文字转语音、声音复刻与音色设计。

### 差异化（三条，均可从竞品证据推出）

**① 跨引擎的统一音色资产。**
两个头部竞品都绑死单引擎：voicebox（★53,982，MIT）与 VoiceStudio（★31,227，AGPL-3.0）的 profile 各自只对应一个引擎。本产品的音色是**引擎无关的逻辑实体**，下面挂多个引擎绑定——因此「同一个音色换引擎唱一遍」这件事，在它们的数据模型里根本无法表达。

**② 引擎能力中立层。**
voicebox 的抽象泄漏是有据可查的反面教材：副语言标签 `[laugh]` 只有 1/7 引擎支持，其余引擎**把它当文本念出来**；`instruct` 字段在 UI 广泛暴露却被多数引擎静默丢弃（issue #185，全仓库互动最高）。本项目的原则是**能力声明必须真正控制 UI 可用性**——引擎不支持的能力，界面直接不给。

**③ 中国大陆可用。**
voicebox 官方 troubleshooting 对大陆用户的答案原文是「Try using a VPN if HuggingFace is blocked in your region」；#546 / #741 两条中国网络 issue 至今 open 无人回应；社区已写好完整 ModelScope 支持（PR #1075）晾了 3 周未合。**「装完就能用、不要求用户有代理」在这个赛道是真空。**

### 三条明确的非目标

- **不做远程推理**（ADR-0005）：每台机器各跑各的，跨机器靠手动导出。
- **不内置平台密钥代调用**（ADR-0003）：一律 BYOK。
- **不做账号体系与云同步**（ADR-0003 / ADR-0005）：全本地存储。

## 3. 架构

```
┌─────────────────────── Electron 外壳 ───────────────────────┐
│  React UI（4 标签页）                                        │
│  波形：wavesurfer.js / peaks.js                              │
└───────────────┬─────────────────────────────────────────────┘
                │  本机 HTTP + WebSocket（日志/进度）
┌───────────────▼─────────────────────────────────────────────┐
│  Python 推理服务（sidecar，127.0.0.1:动态端口 + bearer 鉴权） │
│  ┌────────────┐ ┌──────────────┐ ┌───────────────────────┐  │
│  │ 引擎注册表  │ │ 文本归一化层  │ │ 任务队列（限流/显存）  │  │
│  └────────────┘ └──────────────┘ └───────────────────────┘  │
│  ┌─────────────── 云端适配器 ───────────────┐                │
│  │ 阿里百炼 │ MiniMax │ Fish Audio          │                │
│  └──────────────────────────────────────────┘                │
│  ┌─────────────── 本地适配器 ───────────────┐                │
│  │ macOS：Qwen3-TTS-0.6B（MLX，torch-free） │                │
│  │ Windows：待定（PyTorch + CUDA）           │                │
│  └──────────────────────────────────────────┘                │
└──────────────────────────────────────────────────────────────┘
                │
        数据目录（自包含、可整体拷贝）
        SQLite + 音频文件 + 音色元数据
```

**为什么 macOS 与 Windows 用不同运行时**：PyTorch/MPS 对 TTS 基本不可用（`nn.Conv1d` 的 65536 输出通道上限，IndexTTS 在 M3 Max 上复现；GPT-SoVITS 维护者建议 Mac 用 CPU；XTTS-v2 在 MPS 上 hang）。因此 macOS 走 torch-free 路线（MLX），Windows 走 PyTorch + CUDA，**但对上层暴露同一套协议**。

**必须避开的已知陷阱**

*打包与进程（来自 voicebox 事故）*
- **不用 PyInstaller 冻结 Python**——它的崩溃类别（`_MEI` 缺文件 #212、`No module named` #275、broken pipe #606、server 起不来 #513）全部源于此。
- **不在运行时下载可执行二进制**——它的做法直接导致「Windows 装 .exe 就是没 GPU」（#192）、国内下不动、被 AV 报毒。
- 半成品 `.venv` 必须清理（ComfyUI #1574：否则重试永久失败）。
- 默认只绑 `127.0.0.1` + 强制鉴权（它的 `0.0.0.0` 无鉴权 #934）。

*依赖解析（来自 IndexTTS / VoxCPM 事故，直接威胁 ADR-0002 的运行时）*
- **传递依赖会用 CPU 版 torch 顶掉 CUDA 版**。`funasr` / `modelscope` 这类依赖会从默认 PyPI 索引取 CPU-only 的 `torch`。VoxCPM #60 实测：用户装好 GPU 版后 `torch` 变成 `2.8.0+cpu`、CUDA 不可用、**29 秒音频跑了 700 秒（RTF≈24）**，反复重装无效。
  → 三条硬规范：`torch` / `torchaudio` 必须写成 **project 直接依赖**；CUDA 索引用 `[[tool.uv.index]]` + `explicit = true`，**不用 `--extra-index-url`**；**安装后断言 `torch.cuda.is_available()` 且 `torch.version.cuda` 非空，否则拒绝启动**（而不是让用户跑出 700 秒才发现）。
- **安装路径必须纯 ASCII**。IndexTTS #93：中文路径会让 ninja 生成乱码 `build.ninja` → **BigVGAN CUDA 内核编译失败并静默降级到 torch 实现**（只慢不报错）。⚠️ **本仓库自身路径 `My Projects/声音复刻软件` 同时含空格与中文**，Windows 用户还有 `C:\Users\张三\`、`C:\Program Files\`。→ **已定**：保留现有仓库路径（问题出在构建/安装目录，源码目录不受影响），但 **venv / `TORCH_EXTENSIONS_DIR` / 运行时安装根一律强制 ASCII**（如 `C:\ProgramData\VoiceClone\`）+ 编译失败要在 UI 里说明。
- **torch/torchaudio 版本漂移会静默损坏音频**。IndexTTS #724：TorchAudio 2.9+ 起 `save()` 走 TorchCodec，把 WAV **静默削顶饱和**（不报错、不告警）。→ 逐引擎钉版本、venv 完全隔离、加**输出峰值自检**。

*显存（来自 IndexTTS #630 / #649，至今 open）*
- **显存泄漏已确认且 `unload()` 不够**：连续生成后显存从 12GB 爬到上限、生成结束不释放，到顶后连短文本都变慢；用户原话「Restarting the service frees up the memory」。叠加常驻稳定占用约 10GB。
  → 三层防护：`unload()` + 空闲超时释放 + **达到次数/显存阈值时重启 worker 进程**。

## 4. 领域模型

术语以 `CONTEXT.md` 为准。核心关系：

```
音色 (Voice) ──1:N──> 引擎绑定 (EngineBinding)
   │                        │
   名字/头像/说明            云端 voice_id 或本地模型状态
   参考音频 ← 真相来源       参数
   试听样本                 可用性/健康状态
   │
   └──N:M──> 生成任务 (Generation) ──> 音频产物 + 日志
```

**三条硬规则**：

1. **参考音频是真相来源，云端 ID 是可重建缓存。** 厂商会静默回收音色——MiniMax 7 天未调用即删、百度 1 年无合成调用自动删除、华为云单账号上限 1000 个。因此需要**音色健康检查 → 绑定失效则自动重传重建**。
2. **引擎能力驱动 UI。** 能力维度：语种、复刻、音色设计、发音控制、情感、商业许可、跨设备使用、**上传内容是否用于训练**、全流程能否 API 闭环。引擎不支持的能力，界面不予显示。
3. **生成任务记录血缘。** 参数、成本、耗时、引擎与模型版本全部入账——重跑与偏好画像都依赖它。

## 6. 界面结构

**4 个标签页 + 一条铁律**：实时日志**不能**单独占一个标签页（生成时用户要盯着它），它是「生成」页内的可折叠抽屉。

### 生成
- 文本输入区（含**归一化预览**——让用户看到「2025 年」被展开成什么，避免"为什么读错了"的无解困惑）
- 音色选择器（卡片式，含头像）
- 引擎选择器（**能力矩阵驱动**：不支持的选项直接禁用并说明原因）
- 参数面板（按引擎动态渲染）
- 参考音频上传（**质检诊断**：信噪比 / 单说话人 / 削波 / 静音段 + 修复建议）
- 生成按钮 + 队列状态
- 结果播放器：波形、A/B **盲听对比模式**、打分
- 实时日志抽屉（WebSocket 推送）

### 音色库
- 音色卡片（头像 + 说明 + 试听样本）
- 卡片展开：**该音色在各引擎上的绑定列表**与健康状态
- 音色设计入口（文字描述 → 音色）
- 音色包导出 / 导入

### 历史
- 列表（搜索 / 筛选 / 分页）+ 成本与耗时统计
- 详情（参数 + 日志 + 产物）
- **重跑**：跨标签跳转到「生成」页并预填充（这是你原构思里那条需求的落地方式）

### 设置
- API Key（系统钥匙串）
- 引擎开关与**降级顺序**
- 本地运行时与模型管理（uv 环境、模型下载、磁盘占用）
- **下载源**（ModelScope / 自建 CDN）
- 存储位置、**整库备份 / 恢复**
- 主题、语言
- 合规：声音授权确认、AI 生成内容标记

## 8. 关键风险

| 风险 | 缓解 |
|---|---|

## 9. 未决事项

1. **Windows 侧重型引擎** —— **已定 IndexTTS-2.5**（见 §5）。选它的决定性理由不是榜单分数，而是它是**唯一把「uv + Windows CUDA」当一等需求**的候选：仓库自带 `uv.lock`、为 win32 单独写了依赖分支绕开 `WeTextProcessing`、用 `[tool.uv.extra-build-dependencies]` 让 flash-attn 取预编译 wheel、**基础依赖里没有 fairseq / DeepSpeed / flash-attn / pynini**。
   被排除的直接原因：MegaTTS3 与 dots.tts 依赖 `pynini`（**PyPI 上 146 个平台 wheel 全是 manylinux，win_amd64 = 0**）→ `uv pip install` 解析期即失败；GPT-SoVITS 许可最干净（MIT）但 `pyopenjtalk` / `jieba_fast` 无 wheel，需用户装 MSVC。
   **v1.1 效果档候选**：VoxCPM2（Apache-2.0）；观察名单 LongCat-AudioDiT（MIT、依赖树最干净、中文 SIM 81.8 最高，但必须提供参考文本转写且项目太年轻）。
2. 盲听对比界面的具体形态（评分粒度、对比数量上限）。
3. 偏好画像的具体维度（按语种？按文本类型？按长度？）
4. **真机 3090 实测**：报告里所有 3090 数字都是推算（3090 带宽 936 vs 4090 1008 GB/s），**不得当结论引用**；IndexTTS-**2.5 自身**的 seed-tts-eval 数字官方未公布（表中 1.03/76.5 是 2.0 的）。。

## 10. 建议的下一步

不要先写 UI。按证据显示的风险排序，先做三件低成本验证：

1. **装机路径实测**：干净 Windows（无 Python）+ 干净 macOS，各跑一遍「下 uv → 装 PBS → 建 venv → 装 torch/MLX → 下模型 → 出第一段音频」，记录全部失败点。**这份记录就是第一版安装器需求文档。**
2. **引擎能力矩阵实测**：5 个引擎各跑中文回归集（数字/日期/金额/中英混读 + 多音字），产出**你自己的引擎能力矩阵**——这是产品的核心资产，且无法从任何榜单抄到。
3. **中文听感 A/B**：Qwen3-TTS 本地 vs 阿里 vs MiniMax vs Fish Audio，同一音色同一文本，人工盲听。这是唯一能验证 §5 那张表的方式。
