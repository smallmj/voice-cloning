# 跨平台桌面端技术栈调研报告（macOS + Windows）

> 场景：AI 语音 / TTS / 声音复刻桌面应用。负载特征：本地 Python 推理（torch 系）、需要 GPU（Windows+NVIDIA CUDA / Apple Silicon MPS）、需要音频播放与波形绘制、模型体积 GB 级。
> 调研日期：2026-09-16。**所有数字均来自下列公开来源，未核实的已明确标注。**

---

## 0. 结论速览

1. **"Tauri 比 Electron 小 30 倍"是磁盘体积事实，但对你这个场景是伪优势**——你的模型本身就是 GB 级，Electron 那 200–300 MB 运行时开销在总下载量里可以忽略。真正决定成败的是 Python 集成、音频/波形生态、签名公证工具链成熟度。
2. **内存对比的流行叙事是错的**：在单窗口、Release 构建的实测中，Windows x64 上 Electron 反而比 Tauri 更省（≈93 MB vs ≈154 MB）；macOS arm64 两者接近（≈121 MB vs ≈86 MB）。Tauri 的内存优势体现在**多窗口**和 **Linux**，不在 macOS/Windows 单窗口。[HN 讨论](https://news.ycombinator.com/item?id=44120552)
3. **启动速度 Electron 反而赢**：同套 CI 基准 Release 构建，Windows x64 Electron ≈206 ms vs Tauri ≈711 ms；macOS arm64 ≈640 ms vs ≈2044 ms。Tauri 的劣势来自 Rust 运行时初始化 + WebView 冷启动。[Elanis benchmark](https://github.com/Elanis/web-to-desktop-framework-comparison)
4. **真正的分水岭是"怎么带 Python"**：Electron 侧有 ComfyUI Desktop 这个已量产的答案（Electron + `uv` 管理 venv + node-pty）；Tauri 侧有官方 sidecar 机制且文档明确点名 pyinstaller；PySide6 是唯一能**进程内**跑推理的（但 LGPL 有商业合规成本）。
5. **有强力反例证明两条路都能走通**：**Jan 已经从 Electron 迁移到 Tauri 2**（`tauri.conf.json` schema 为 `config/2`，roadmap issue 明说"Electron 体积太大了"）；**Stability Matrix 用 Avalonia（C#/.NET）** 也量产了 AI 桌面应用。

## 2. Tauri 2 成熟度与坑

### 2.1 时间线与成熟度
- **Tauri 2.0 正式版于 2024-10-02 发布**，[官方博客](https://v2.tauri.app/blog/tauri-20/)与 [GitHub Release `tauri-v2.0.0`](https://github.com/tauri-apps/tauri/releases/tag/tauri-v2.0.0)（published 2024-10-02T13:23:35Z）双证。距调研日期已近 2 年，**不算新框架**。
- 2.0 的实质变更：allowlist 机制废除改为 capabilities/permissions 体系；IPC 层重写支持 Raw Payload（避免大数据 JSON 序列化开销）；支持移动端（iOS/Android）；通过 NLNet/NGI 资助做了**外部安全审计**（[官方博客](https://v2.tauri.app/blog/tauri-20/)）。
- 生态规模：2.0 发布时 GitHub 上关闭了 ~4,878 PR / ~3,570 issue，Discord ~17,700 成员（[同上](https://v2.tauri.app/blog/tauri-20/)）。对比 Electron 的社区知识存量（VS Code/Slack/Discord/Figma 等）仍差一个量级。

### 2.2 WebView 分裂：这是 Tauri 最大的架构性风险
- Tauri 不打包引擎：Windows 用 **WebView2（Chromium）**、macOS 用 **WKWebView（WebKit）**、Linux 用 **WebKitGTK**（[官方 webview-versions](https://v2.tauri.app/reference/webview-versions/)）。
- **macOS 的 WebKit 与系统版本绑定**："unsupported macOS versions do not receive WebKit updates"——即旧版 macOS 用户会拿到旧 WebKit 内核。对音频应用这是实打实的风险（Web Audio / MediaRecorder / AudioWorklet 的成熟度随 Safari 版本显著变化）。
- Linux 的 WebKitGTK 问题最严重（虽超出你 macOS+Windows 的范围，但影响开发者本机调试）：窗口白屏、resize 崩溃、`AcceleratedSurfaceDMABuf` 报错、Wayland `Error 71`。[Tauri 官方 Linux Graphics Issues 页](https://v2.tauri.app/develop/debug/linux-graphics/)提供了 4 级 workaround（`__NV_DISABLE_EXPLICIT_SYNC=1` → `WEBKIT_DISABLE_DMABUF_RENDERER=1` → `WEBKIT_DISABLE_COMPOSITING_MODE=1`），原始报告为 [tauri-apps/tauri#9394](https://github.com/tauri-apps/tauri/issues/9394)。

### 2.3 具体已知缺陷（可溯源的 issue 编号）
| Issue | 日期 | 问题 |
|---|---|---|

### 2.4 Windows WebView2 分发：三种模式尺寸代价明确
官方给出成本表（[Windows Installer 文档](https://v2.tauri.app/distribute/windows-installer/)）：

| 模式 | 需联网 | 安装包增量 |
|---|---|---|
| `downloadBootstrapper`（默认） | 是 | 0 MB |
| `embedBootstrapper` | 是 | ≈1.8 MB |
| `offlineInstaller` | 否 | **≈127 MB** |
| `fixedVersion` | 否 | **≈180 MB** |
| `skip` | 否 | 0 MB（官方标注 ⚠️ 不推荐） |

**实务提醒**：Windows 10 (2018-04 后) / Windows 11 已将 WebView2 作为系统组件分发，所以离线打包多数场景不必付这 127–180 MB。但反过来说——**如果你为了离线分发打了 fixedVersion，Tauri 的体积优势会被吃掉一大半（5 MB → 185 MB）**，此时与 Electron 的差距从 30 倍缩到 ~1.7 倍。

### 2.5 多窗口 / 托盘 / 文件系统权限
- 多窗口与托盘为官方能力（System Tray 有独立官方指南）。Jan 的 `tauri.conf.json` 中配置了 `macOSPrivateApi: true` 及多个窗口 capability（`log-app-window`、`logs-window`、`system-monitor-window`、`mlx`），说明产线级多窗口 + MLX 集成可行（[Jan tauri.conf.json](https://github.com/janhq/jan/blob/dev/src-tauri/tauri.conf.json)）。
- 权限模型从 allowlist 换成 capabilities/permissions 后**更细粒度但迁移成本高**，社区主要抱怨点集中在文档与示例不足（HN 用户 KronisLV："最大的障碍就是文档和示例，因为大家都用 Electron，那边的集体知识最多"，[HN](https://news.ycombinator.com/item?id=44120552)）。

### 2.6 构建耗时与开发体验
- Rust 编译导致首屏构建慢：空壳 App Windows x64 Electron ≈11 s vs **Tauri ≈250 s**（[Elanis](https://github.com/Elanis/web-to-desktop-framework-comparison)）；Hopp 实测 15.8 s vs 80.9 s（[Hopp](https://dev.to/gethopp/tauri-vs-electron-performance-bundle-size-and-the-real-trade-offs-1el4)）。
- ⚠️ **基准数据可靠性警告**：Elanis 基准在 GitHub CI 上跑，Tauri Linux 启动显示 ≈30 s，HN 上被直接质疑"数量级错误"（[HN](https://news.ycombinator.com/item?id=44120552)）。引用其中任一数字都应带上这个前提。

### 2.7 移动端对桌面端的影响
Tauri 2 的移动端支持是**双刃剑**：Jan 的迁移动机之一正是"Electron 内嵌 Chromium 和 Node.js，不适合扩展到移动端"（[Jan roadmap #4485](https://github.com/janhq/jan/issues/4485)，2025-01-20）。但移动端的引入也带来了配置复杂度（capability 需按平台区分、多窗口在移动端语义不同）。

## 3. Electron 体积 / 内存实测数据

- **磁盘体积**：空壳 Release 构建 Windows x64 ≈384 MB、macOS arm64 ≈319 MB（[Elanis](https://github.com/Elanis/web-to-desktop-framework-comparison)）；Hopp 单测 244 MiB（[Hopp](https://dev.to/gethopp/tauri-vs-electron-performance-bundle-size-and-the-real-trade-offs-1el4)）。Electron 核心维护者 Felix Rieseberg 直言"大多数 Electron 应用落在 **100 到 300 MB**"（[felixrieseberg.com](https://felixrieseberg.com/things-people-get-wrong-about-electron/)，2025-01-21）。
- **内存**：单窗口 Release 实测 macOS arm64 Electron ≈121 MB vs Tauri ≈86 MB；**Windows x64 Electron ≈93 MB vs Tauri ≈154 MB——Electron 更省**（[HN 引 Elanis 数据](https://news.ycombinator.com/item?id=44120552)，2025-05-28）。多窗口场景（6 窗口）则逆转：Electron ≈409 MB vs Tauri ≈172 MB（[Hopp](https://dev.to/gethopp/tauri-vs-electron-performance-bundle-size-and-the-real-trade-offs-1el4)）。
- **内存是真实痛点**：Cherry Studio（Electron 44）有用户 issue 标题即"[cherry-studio consumes too much memory, can modules be toggled?](https://github.com/CherryHQ/cherry-studio/issues/13737)"（2026-03-23），另一 issue 记录了 [renderer 进程多次 OOM 崩溃与内存泄漏](https://github.com/CherryHQ/cherry-studio/issues/12925)。
- **AI 应用的实例数据**：LM Studio 有官方 bug 标题为"[LM Studio version of Electron causes slowdowns on Macs running MacOS 26](https://github.com/lmstudio-ai/lmstudio-bug-tracker/issues/1144)"（2025-10-23），另有 log 目录涨到 ~8.22 GB 触发 **V8 heap OOM** 的崩溃单（[#1754](https://github.com/lmstudio-ai/lmstudio-bug-tracker/issues/1754)，2026-04-04）——V8 堆这个错误类型本身就确证了 Electron/Node 架构。
- ⚠️ 第三方流传的"Electron 187 MB vs Tauri 14.2 MB"之类数字（johal.in 等站点）**不可信**：该站同批文章还包含"Flutter 4.0 自动更新"这类不存在的版本号，以及日期矛盾的事故复盘。本报告一律不采信。

## 5. 推荐（首选 + 备选）与理由、风险

### 首选：Electron + React + Python sidecar（`uv` 管理 venv，PyInstaller/`uv` 分发）

**理由**
1. **Tauri 的体积优势在本场景不成立**。模型是 GB 级；Electron 运行时 200–300 MB 只占总量个位数百分比。若为离线分发再打 WebView2 fixedVersion（+180 MB），差距基本抹平（[Tauri 官方数据](https://v2.tauri.app/distribute/windows-installer/)）。
2. **单窗口内存上 Electron 并不输**（Windows x64 实测 Electron ≈93 MB vs Tauri ≈154 MB，[HN/Elanis](https://news.ycombinator.com/item?id=44120552)）。真正的内存压力来自 torch 模型本身，不来自 UI 层。
3. **Python 集成有量产级参考实现**：ComfyUI Desktop 的 `uv` venv + node-pty 方案可直接借鉴，[源码可读](https://github.com/Comfy-Org/desktop/blob/main/src/virtualEnvironment.ts)。这比 Tauri sidecar 少一层 Rust 胶水。
4. **音频/波形生态碾压对手**：`wavesurfer.js` 与 BBC 的 [`peaks.js`](https://github.com/bbc/peaks.js) 开箱即用，Web Audio API 提供 AudioWorklet / AnalyserNode 等实时处理能力；PySide6/Flutter/Avalonia 都要自己拼。
5. **签名公证 + 自动更新工具链最成熟**：`@electron/notarize` + electron-builder 是行业内走得最多遍的路；electron-updater 在 macOS 走 Squirrel.Mac（[Electron 官方文档](https://github.com/electron/electron/blob/main/api/auto-updater.md)），只需注意 **macOS 必须签名否则更新不工作**、**electron-builder 不支持 Squirrel.Windows**（[官方文档](https://www.electron.build/docs/features/auto-update/)）。
6. **人才与踩坑资料**：VS Code / Slack / Discord / Figma / ChatGPT / Claude / Notion / 1Password / Docker Desktop 均为 Electron（[Felix Rieseberg](https://felixrieseberg.com/things-people-get-wrong-about-electron/)），招人、检索、AI 编码助手训练数据密度都最优。

**风险与缓解**
- **渲染进程内存泄漏**是真实事故源（Cherry Studio [OOM issue](https://github.com/CherryHQ/cherry-studio/issues/12925)）。→ 立项即把"长时运行内存基线 + 自动化泄漏检测"写进验收标准，不要等到用户投诉。
- **多窗口内存线性增长**（6 窗口 409 MB）。→ 主窗口 + 设置页用路由而非新开窗口；波形/编辑器尽量单窗口内切换。
- **安装包 300 MB+ 的观感问题**。→ 首启只下壳体（<100 MB），模型按需下载并复用系统缓存目录；在 UI 上把"模型另计"讲清楚。

### 备选 A：Tauri 2 + React + Python sidecar

**适用条件**（满足其一才值得换）：① 你有一个**不含模型**的轻量云推理版要发（此时 3–5 MB 的壳是真优势）；② 明确要延伸到 iOS/Android（Jan 的动机，[#4485](https://github.com/janhq/jan/issues/4485)）；③ 团队已有 Rust 能力。

**理由**：官方 sidecar 明确支持 pyinstaller 打包的 Python（[官方文档](https://v2.tauri.app/develop/sidecar/)）；Jan 已证明可行；安装包 3–5 MB；官方 updater 插件存在。

**风险**
- macOS WebKit **随系统版本走**，旧 macOS 用户拿到旧内核（[官方文档](https://v2.tauri.app/reference/webview-versions/)）——对 Web Audio / AudioWorklet 是硬约束，需要把**最低支持 macOS 版本**拉到足够高。
- WKWebView 与 Chromium 的音频行为差异已被记录：[WKWebView 内 `HTMLAudioElement` seek 毛刺、`playbackRate` 变更问题](https://developer.apple.com/forums/thread/829729)。音频类应用需为 WebKit 单独做兼容测试。
- [issue #14263](https://github.com/tauri-apps/tauri/issues/14263)：弹窗被无差别拦截，影响 OAuth 类流程。
- 构建慢（首次 Windows ≈250 s）、Rust 学习曲线、社区示例少（[HN](https://news.ycombinator.com/item?id=44120552)）。

### 备选 B：PySide6（纯 Python）

**适用条件**：团队纯 Python、推理同进程、且**已评估 LGPL 合规**。

**理由**：唯一无 IPC 的方案，`import torch` 直接用；PyInstaller `--onedir` 实测 ≈118 MB（[实测](https://dev.to/kerfiq/pyside6-vs-electron-why-i-shipped-a-118-mb-windows-desktop-tool-not-a-250-mb-cross-platform-one-2gfl)）。

**风险**
- **许可证**：Qt for Python 为 LGPLv3/GPLv3 或商业版（[官方](https://doc.qt.io/qtforpython-6/commercial/index.html)、[licenses](https://doc.qt.io/qtforpython-6/licenses.html)）。闭源商业分发需满足 LGPL 动态链接+可替换义务，或购买商业许可——**这是成本项，不是免费的**。
- 打包 torch + Qt 体积膨胀明显（PyInstaller 对 Qt 6 的支持历史上曾有缺口，[官方部署文档](https://doc.qt.io/qtforpython-6/deployment/deployment-pyinstaller.html)；Nuitka 为替代路径）。
- 波形/动效生态远弱于 Web；毛玻璃需平台专有 API。

### 不推荐
- **Flutter Desktop**：桌面音频插件质量参差、无非 CSS 的成熟波形库、团队要学 Dart，且对本场景**没有任何一项决定性优势**。
- **.NET MAUI**：Linux 目标尚不支持（[Elanis 基准](https://github.com/Elanis/web-to-desktop-framework-comparison)），桌面打磨与生态弱于 Avalonia（[对比文](https://chudovo.com/choosing-between-avalonia-ui-and-net-maui-for-desktop-development/)）。
- **Avalonia（可作为第三备选）**：技术上完全能跑（Stability Matrix 已量产），但你会得到 **C# + Python 两套非前端语言**，且音频/波形库厚度不如 Web。除非团队本命是 .NET，否则不划算。

## 6. 关键成本速查

| 项目 | 金额 | 来源 |
|---|---|---|
| Apple Developer Program | **$99/年** | [Tauri 签名文档](https://v2.tauri.app/distribute/sign/macos/) |
| Windows OV 代码签名证书 | **$150–300/年** | [Microsoft Learn](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options) |
| Windows EV 代码签名证书 | **$400+/年** | 同上 |
| 硬件令牌 / 云 HSM（2023-06-01 起**强制**，含非 EV 证书） | 视 CA，通常按年或按签名次数计费 | [CA/B Forum BR](https://cabforum.org/working-groups/code-signing/requirements/) |
| Azure Trusted Signing | 见 Microsoft 定价 | [Microsoft Learn](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options) |

> **务实提醒**：Windows 签名现在必须走云 HSM 或硬件令牌，CI 里"把 .pfx 塞进 secret"的老做法**在 2023-06 之后已不合规**。Tauri 官方文档给出了 [GitHub Actions + Azure Key Vault 的完整流程](https://v2.tauri.app/distribute/sign/windows/)，Electron 侧需自行接 signtool / Azure Trusted Signing。

## 7. 未核实项（明确标注，请勿当结论使用）

1. PySide6 / Flutter / Avalonia 的**冷启动时间**与**空窗口内存**没有找到同口径公开基准（Elanis 的 Flutter/MAUI 列多为 N/A 或数据不全）。
2. AnythingLLM 桌面端的具体打包依赖文件未定位到（仅有 README 声称提供桌面版）。
3. Witsy 的技术栈未核实（仓库存在，但清单文件读取失败）。
4. Ollama 桌面版的框架**未从源码二次确认**，仅依据官方博客日期与第三方架构描述。
5. Tauri [issue #13141](https://github.com/tauri-apps/tauri/issues/13141) 的创建日期未核实（搜索摘要未给出）。
6. 所有 Elanis 基准数据来自 GitHub CI，含未量化的系统噪声（Tauri Linux 启动 ≈30 s 已被 HN 读者质疑），**只可用于同平台横向比较，不可当作绝对性能指标**。
