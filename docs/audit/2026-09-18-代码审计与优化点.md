## 0. 摘要

- **52 条**代码缺陷 + **3 条引擎级语义缺陷**（引擎接受了参数但从不使用）。
- **3 条 P0**：本地转写下载必崩、`VOICECLONE_*` 覆盖在应用里全部失效、引擎选择不持久化。另有 1 条 P0 级的**正确性**问题：生产环境里唯一的"云端转写"提供方是测试替身，会把写死的测试文本写进用户音色库。
- **当前不具备"交付给用户"的条件**：没有任何打包管线（`app/package.json` 无 package/dist 脚本，依赖里没有 electron-builder/forge/packager），而 `electron/main.ts` 自述"打包构建留待后续工单"。macOS 上从 Finder 启动的 `.app` 继承 launchd 的最小 PATH，`spawn("uv")` 会失败。
- **无 CI、无 linter/格式化配置、无 README/Makefile、前端零测试**；328 个测试节点只靠人记得才跑，而唯一的挂死保护（pytest-timeout）已丢失且未声明。
- **文档漂移 6 处**，其中决策 #6（SQLite）与 #18/#19（标签页/双主题）是大量下游发现的根因。

### 参数不可等价（共享控件会产出静默错误的音频）

- **IndexTTS `duration_factor` 是时长倍率，与所有引擎的 speed 相反** → "更快"会变慢。
- **`repetition_penalty` 在 IndexTTS 是 10.0、在 mlx-audio 是 1.05**。
- **「音高」有四种互不兼容单位**（半音 [-12,12] / [-100,100] / **比值** [0.5,2.0] / `shift the pitch by N step(s)`）；**MiniMax 一个请求体内有两个不同单位的 `pitch`**。
- 情感枚举两两不同；语种方案六套且有一个引擎根本没有该参数；**六个引擎合计 30+ 个参数条件性或无条件失效**。

## 10. 更高的杠杆：归并后的主题

审计的 52 条按主题归并后是 13 个 issue（见 §11）。按杠杆排序：

4. **修别名可变记录 + 泛化 JSON 索引**（`generations.py:70-75`、`main.py:1092-1096`）——一次改动同时消除撕裂日志竞态与平方级重写。（本仓库选择改用 SQLite，见 ADR-0017。）
5. **把阻塞活移出事件循环并给 `loudness.py` 加上限**（`main.py:448-460,544,569,585,621`；`loudness.py:64-71,144-146,197-233`），以 `diagnostics.py:185-192` 为仓内模板。
6. **停止从回归线程向主循环队列投递**（`main.py:99-107,1699-1700,1759-1764`），并串行化回归运行。
7. **修三处前端生命周期缺陷**（`App.tsx:1190/1808/346`、`1385-1448`、`1432-1439`）。
8. **打包应用**：内嵌 uv 并用绝对路径引用（`electron/main.ts:19-23,48`）、加 `app.requestSingleInstanceLock()`（`:129-135`）、修 Windows 上的 `os.uname()` 并钉住 uv 版本（`uvman.py:43-49,78-81`）。
