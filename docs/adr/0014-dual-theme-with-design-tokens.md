# 0014 — 深色为默认的双主题，令牌化设计系统，不引入 CSS 框架

日期：2026-09-18 · 状态：已采纳 · 关联：plan §2 #19

## 背景

plan §2 #19 定的是「双主题 + 跟随系统，默认深色，专业工具风」，同样**从未实现**。`app/src/styles.css` 只有一套硬编码深色（`color-scheme: dark` 加 6 个自定义属性），没有 `prefers-color-scheme`、没有浅色配色、没有主题状态与持久化。

已核实的实际问题**不是"缺设计系统"**，而是**两个时代粘在一起**：L1–127 使用令牌且配色自洽；L130–379（后续 issue 追加）在深色背景上写浅色主题的原始 hex。后果里有几条不是观感问题：

- `.pref-table th { background: #f5f5f5 }` 配继承的 `#e6e8ee` 文字 → 对比度 ≈ **1.05:1**，能力矩阵与偏好画像的表头**完全不可读**。
- `.engine-note { color: #555 }` / `.engine-note-label { color: #333 }` → 设置页的**「计费口径」与「数据与训练」披露近乎不可见**。这是**合规关键路径**：MiniMax 的 ToS 保留「为改进算法或增强服务使用信息」的权利，这条披露必须可见；plan §5 也早已要求 Fish Audio 的训练用途说明「必须在引擎选择处显示」。
- `.voice-transcript { color: #444 }`、`.diag-advice { color: #666 }`、`.job-status { background: #eee }`（未设 `color`，浅底配继承的浅字）同类失效。
- 零 `:focus` / `:focus-visible` 规则（键盘操作完全没有焦点提示）、零 `@media`、零 `transition`；没有间距/字号/圆角/阴影/语义色标尺；单列硬编码 `max-width: 860px`；`.hint { color: #ffb74d }` 是全应用约 25 处说明文字**唯一**的样式（于是所有提示看起来都像警告）；`.history-empty` 被引用但没有任何 CSS 规则。

另一个已核实的事实：**渲染层没有任何 inline style**（`style={{…}}` 出现 0 次）。所以问题不在"缺少样式机制"，而在令牌只被用了一半、且缺标尺与交互态。

## 决策

1. **不引入 CSS 框架或组件库。** 渲染层只有 4 个源文件（`App.tsx` / `api.ts` / `main.tsx` / `styles.css`），依赖只有 react、react-dom、wavesurfer.js。引入 Tailwind 需要重写 379 行样式并新增一条构建链，收益为负。
2. **补完令牌标尺**：颜色按语义分层（背景 / 表面 / 边框 / 三级文字 / 强调 / 成功 / 警告 / 危险），间距以 4px 为基准，并建立字号阶梯、行高、圆角、阴影与动效时长。
3. **深色为默认 + 浅色主题 + 跟随系统**；令牌是唯一真值来源，主题切换只切令牌，不写第二套选择器。
4. **观感方向 = 专业工具的密度 + 现代细节打磨**：密度、配色克制与等宽数字按工具风；圆角、过渡、焦点态与阴影层次按现代风。强调色沿用现有的冷蓝 `#82b1ff`（波形进度色已在用，避免两处强调色不一致）。
5. **披露类文本属于合规关键路径**，不得使用低对比度色；文字对比度按 WCAG AA（正文 ≥4.5:1）验收，**浅色主题同样**。
6. **删除 L130 之后的浅色 hex 尾巴**，逐条改成语义令牌；`.hint` 改用语义色而不是固定的橙色。

## 后果

- 浅色主题需要单独做一轮对比度校验：同一语义令牌在两套主题下都必须过 AA。
- 本 ADR 与 ADR-0013（分区 + 左侧导航）同批落地——新界面不得新增任何一次性颜色或手写间距。
- 控件规范（按钮、输入、下拉、卡片、徽标、表格、进度、抽屉、模态、toast、导航项）另行成文，不在本 ADR 重述；本 ADR 只定令牌与方向。
- 主题选择需要持久化位置。数据根目录是整库备份/恢复的搬运单位，因此"跟随系统 / 强制深色 / 强制浅色"属于库的属性，写入 sidecar 的设置存储而不是 localStorage（与 ADR-0012 对同意状态的处理一致）。
