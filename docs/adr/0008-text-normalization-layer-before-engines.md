# 文本在进入任何引擎之前，先经过自建的归一化层

所有待合成文本先经过一层统一的文本归一化（数字、日期、金额、单位、中英混读），再交给引擎。**不依赖各引擎自己处理。**

**为什么这是一个架构决定而不是一个工具函数**：实测证据表明引擎的文本处理不可靠——Chatterbox 把参考音频里的「2025 年 / 100 万」读成乱码，日志给出的线索是 `pkuseg not available - Chinese segmentation will be skipped`。而三个云端引擎 + 两个本地引擎各有各的读法与失败模式，无法统一修复。

**两条支撑理由**：
1. 这是**可用性底线**，不是增值功能——不归一化则中文输出直接不可用。
2. 它是**盲听对比公平性的前提**。若各家引擎自行处理数字，用户比较到的将是"谁的文本处理 bug 更少"，而不是"谁的音质更好"，这会让交叉试听的核心功能失去意义。

**Consequence**：归一化层成为所有生成路径的必经节点，任何引擎适配器都不得绕开；需要一份**中文数字 / 日期 / 金额 / 中英混读回归集**作为验收标准，它是该层的规格说明。多音字（拼音标注）**不在本层范围**——调研显示只有 IndexTTS2 与 CosyVoice3 有正式的多音字纠错机制，它属于引擎能力，必须按引擎在界面上开关，否则就是 voicebox 式的抽象泄漏。
