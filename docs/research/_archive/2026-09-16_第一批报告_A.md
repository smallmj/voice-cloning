### 1.7 已知坑

1. **参考文本泄漏 / 幻觉（最经典）** — issue #85：参考音频里的句子（例："our love of chocolate"）会**被追加到生成结果末尾**，长文本时可能**重复 2–3 次**。README 也承认"To avoid possible inference failures..."并给了一整节规避指引。
2. **长文本语速失控** — issue #811：中文 200 字正常，300 字开始变快，**500 字快到听不清**。
3. **微调后英文单词重复** — issue #636。
4. **30 秒硬上限** — 单次生成 prompt+输出合计 ≤30s，必须靠 chunk 拼接；参考音频裁到 ~12s。
5. **大写字母会被逐字母朗读**（如 `KFC` 应写成 `K.F.C.`）；中文数字需预处理。
6. **输出静音时先查 FFmpeg 是否安装**（官方 FAQ）。
7. **MPS 算子覆盖不全** — `aten::unfold_backward` 等未实现，靠 `PYTORCH_ENABLE_MPS_FALLBACK=1` 回落 CPU，会拖慢速度。
8. **无 LoRA** — 只支持全参微调，对单说话人复刻场景成本偏高（issue #910 讨论中官方确认）。

### 2.7 已知坑

1. **许可陷阱（最大坑）** — 见 §2.4。很多人仍按"Apache-2.0"理解 fish-speech，**这是错的**。
2. **显存回归** — v1.5.1 启动显存从 1.8GB 涨到 5.8GB（issue #1144），8GB 卡用户被劝退回 v1.5.0。
3. **MPS 崩溃** — issue #789 的 dtype 断言错误；MPS 路径未在 CI 中被系统性测试。
4. **S2 Pro 门槛陡增** — 24GB 显存 + Linux/WSL 硬要求 + 11GB 磁盘 + Gated 下载。
5. **依赖钉死** — `torch==2.8.0`、`transformers<=4.57.3`、`modelscope==1.17.1`，与已有项目环境容易冲突。
6. **Gated 仓库** — 下载 S1-mini / S2 Pro 都需要 HF 登录并勾选非商业承诺，自动化部署需配置 token。
7. **v1.5.1 README 提到的遗留问题** — Fish Agent 部分自述"early alpha test version, the inference speed needs to be optimised, and there are a lot of bugs waiting to be fixed"。

### 3.7 已知坑

1. **（官方自认）稳定性差** — README FAQ #2 原文："**Model stability is not good enough, with issues such as multi speakers or poor audio quality.** This is a problem that typically occurs with autoregressive models (for bark and valle). It's generally difficult to avoid. **One can try multiple samples to find a suitable result.**" —— 即**需要"抽卡"**，不适合生产级确定性输出。
2. **音质被人为劣化** — 训练时加入高频噪声 + MP3 压缩（官方为反滥用有意为之），因此**音质天生不如同代其他模型**，且这是设计选择、不会修复。
3. **开源版无 SFT** — 只有 40k 小时预训练基座（主模型 100k 小时 + SFT 未开源），所以效果与官方演示有差距。
4. **英文实验性** — 官方示例直接注释 "English is still experimental."
5. **控制能力弱** — 词级只有 3 个 token；多情感控制仍在 roadmap 未实现。
6. **AGPL + NC + 学术用途三重许可阻断商用**。
7. **MPS 内存泄漏** — 官方不推荐。
8. **HF 权重长期未更新**（2024-10-22 至今），社区活跃度下降。

### 5.7 已知坑

1. **最大坑：拿不到 WaveVAE 编码器** — 无法自建 `.npy`，必须把参考音频发给字节走 request queue 人工审核（≤24s/条）。**这直接决定了它能不能产品化**。
2. **只能 Linux + NVIDIA** — macOS 完全无解（issue #45），Windows/Docker 都还是 "under testing"。
3. **`WeTextProcessing` / `pynini` 编译地狱** — 依赖 OpenFst，跨平台安装是主要失败点。
4. **CPU 极慢** — 官方："about 30 seconds (for 10 inference steps)"。
5. **无流式、无微调代码**、"精细发音/时长调整"永远 coming soon。
6. **`p_w` / `t_w` 需要手工调参** — README 原文："Typically, prompt with more noises requires higher p_w and t_w"，调不好会有口音残留或音色不像。
7. **项目更新停滞** — 自 2025-03-22 发布后无功能更新。
8. **中文效果未公开量化** — 论文只报了英文 LibriSpeech，中文表现**未核实**（README 声称支持，但无数字支撑）。

| MaskGCT (gt length) | 0.777 | 2.183 | 0.101 | 4.11±0.12 | 0.08±0.18 |

**关键解读（重要，避免误判）：**
- ✅ **SIM（音色相似度）是 MaskGCT 的绝对强项**：test-zh SIM-O **0.774**，**超过 Ground Truth 的 0.750**；test-en 0.717 也接近 GT 0.730。这是它"像本人"的核心竞争力。
- ⚠️ **但 WER 明显落后于 F5-TTS**。第三方论文（Spark-TTS Table 4、F5-TTS 论文）一致：test-en **F5-TTS 1.83% vs MaskGCT 2.62%**；test-zh **F5-TTS 1.56% vs MaskGCT 2.27%**。MegaTTS3 论文也把 MaskGCT 列在 SIM-O 0.69 / WER 2.63%。
- 📌 **一句话定位：MaskGCT = 音色最像、但念得没那么准、且吃 16GB 显存。**

**社区口碑：** 学术声誉高（ICLR 2025、Amphion 生态、SIM 指标亮眼），但**工程口碑一般**：显存门槛高（>16GB）、依赖老（torch 2.0.1）、`espeak-ng` 系统依赖、Mac 完全跑不起来、生成慢（3090 Ti 上 5-6 秒出 10 秒音频）。**且已被自家 Metis 取代**。

### 6.6 工程可用性

| 项 | 结论 |
|---|---|
| 官方 pip 包 | ❌ **无官方包**。⚠️ **PyPI 上的 `maskgct` 是第三方包**：`maskgct` **0.0.19（2024-11-19）**，自述 "**MaskGCT convenient inference wrapper**"，**license 写 GPL-3.0**（注意：这与官方 Amphion 的 MIT **不一致**，是第三方作者的许可选择）→ **不建议用于产品** |
| 硬依赖 | ✅ **无 fairseq、无 DeepSpeed、无 flash-attn**。`models/tts/maskgct/requirements.txt`：**`torch==2.0.1`（钉死在 2023 年版本，最大兼容性痛点）**、`transformers==4.41.2`、`accelerate==0.24.1`、`numpy==1.26.0`、`scipy==1.12.0`、`onnxruntime`、`librosa`、`encodec`、**`phonemizer`**、`g2p_en`、`jieba`、`cn2an`、`pypinyin`、`LangSegment`、**`pyopenjtalk`**（需编译）、`pykakasi`、`json5`、`ruamel.yaml`、`gradio`、`openai-whisper` |
| ⚠️ 系统依赖 | **必须 `apt-get install espeak-ng`**（phonemizer）；Windows 需下载 .msi |

| GGUF / llama.cpp | ❌ 未找到 → 未核实/无 |
| **API 服务器** | ❌ **只有 Gradio** — `python -m models.tts.maskgct.gradio_demo`；另有 Jupyter notebook `maskgct_demo.ipynb` 与脚本 `maskgct_inference.py`。**无 FastAPI / HTTP API server** |
| 安装方式 | ⚠️ Amphion 仓库很大，官方推荐 **sparse-checkout 部分克隆**：`git sparse-checkout set models/tts/maskgct` 然后 `sparse-checkout add models/codec utils` |
| 权重路径 | 4 个独立 checkpoint：Semantic Codec / Acoustic Codec / MaskGCT-T2S / MaskGCT-S2A（HF `amphion/MaskGCT`） |
| Star / 活跃度 | Amphion 整体 **10,295 stars**，最后提交 **2026-03-25**（在发 Vevo2），**但 MaskGCT 子模块自 2025-04 起静默**；HF 权重最后修改 2025-04-13 |
| 相关产品 | 官方公测产品"**趣丸千音**"（`voice.funnycp.com`）|

### 6.7 已知坑

1. **显存门槛高** — 官方 Gradio playground **<16GB 直接 OOM**（issue #328 在 7.75GB 卡上失败）；issue #344 实测 ~12GB + 100% GPU 占用，无法同卡跑第二个实例。
2. **`torch==2.0.1` 钉死** — 2023 年版本，与任何现代 PyTorch 生态（CUDA 新版本、transformers 新版）冲突，几乎必须独立 conda 环境。
3. **macOS / MPS 完全不可用** — 中文 G2P 的 onnxruntime 报错（issue #415）+ `LangSegment` ImportError（issue #450）。
4. **`espeak-ng` 系统依赖** — 部署时容易漏装导致 phonemizer 初始化失败。
5. **`pyopenjtalk` 编译问题** — 需要本地编译工具链。
6. **生成速度慢** — 3090 Ti 上 5-6 秒生成 <10 秒音频（约 RTF 0.5）。
7. **权重 NC** — 不可商用。
8. **已被 Metis 取代** — 新需求应直接评估 Metis（支持 VC 等 5 类任务）而非 MaskGCT。
9. **长文本无官方评测** — 未核实。
10. **PyPI 上的 `maskgct` 是第三方 GPL-3.0 包** — 不要误以为它是官方，也注意 GPL 传染性。

## 7. 横向总结与选型建议

### 7.1 按你的实际目标（"声音复刻软件"，疑似商业桌面 App）排序

**许可安全度排序（从高到低）：**

1. 🥇 **MegaTTS3** — 代码+权重均 **Apache-2.0**，唯一许可上可商用打包的。**但必须先解决 WaveVAE 编码器闸门**（否则无法为新音色做零样本克隆）。技术栈限 Linux+NVIDIA。
2. 🥈 **Spark-TTS / F5-TTS / MaskGCT** — 代码宽松（Apache-2.0 / MIT / MIT），**权重全部 CC-BY-NC**。若能把权重替换为自训练/自有授权的模型，则代码可直接商用；否则不可。
3. 🥉 **Fish-Speech** — 当前 main 是自研研究许可，**明确禁止商业用途（含企业内部使用）**，且不可再授权。**风险最高，不建议纳入商业产品**（除非签约）。
4. ❌ **ChatTTS** — **AGPL-3.0 传染性** + 模型 NC + "仅学术用途" 三重阻断。对闭源桌面软件**不可用**。

> **务实的路：** 若目标是商业桌面声音复刻，本批 6 个**没有一个能直接白嫖**。可行路径有三：①与 MegaTTS3 的持有方沟通拿到 WaveVAE 编码器；②用宽松代码（F5-TTS MIT / Spark-TTS Apache-2.0）搭框架，**用自有数据或已授权数据自训练权重**（绕开 NC 权重）；③评估许可真正开放的替代模型（如 Apache-2.0 / MIT 权重的模型族），本批未覆盖。

### 7.2 按 Apple Silicon（MPS）目标排序

若产品要跑在 Mac 上，可选面被极度收窄：

| 可用度 | 模型 | 说明 |
|---|---|---|
| ✅ **首选** | **F5-TTS** | 唯一有官方 MPS 分支 + MPS fallback + arm64 依赖适配的；**外加 `f5-tts-mlx` 原生 MLX 路线（4/8bit 量化，M3 Max 约 4 秒）**。**Mac 上唯一真正可工程化的选择** |
| ⚠️ 实验性 | ChatTTS | `experimental=True` 可开，但官方说"slow + memory leak"，不推荐 |
| ⚠️ 部分 | Fish-Speech | `--device mps` 已合并但会崩（dtype 错误）；S2 Pro 官方不认 Mac |
| ❌ 不可用 | Spark-TTS | MPS 报 `NotImplementedError`，只能 CPU |
| ❌ 不可用 | MaskGCT | Mac 上 onnxruntime + LangSegment 双报错 |
| ❌ 不可用 | MegaTTS3 | Mac 安装直接失败，无任何 MPS 支持 |

### 7.3 工程易用性总排序（脱离许可看）

1. **F5-TTS** — 官方 pip、零重依赖、无 fairseq/DeepSpeed/flash-attn、Gradio+socket+Triton 全套、ONNX/MLX/GGUF 三条社区量化路线、最活跃。**综合第一**。
2. **ChatTTS** — 官方 pip、内置 FastAPI + OpenAI 兼容 API、内置 ONNX 导出、4GB 显存门槛最低。**但质量与许可拖累**。
3. **Fish-Speech** — 生产级 SGLang/vLLM 支持、Kui API server、Docker+ROCm、LoRA 微调，但 24GB 显存 + Linux/WSL + 依赖钉死 + 许可收紧。
4. **Spark-TTS** — 依赖极干净（5 个主依赖）、Qwen2.5 生态友好、0.5B 轻量、有社区 ONNX/GGUF；**但停更 + 无 API server + MPS 挂**。
5. **MegaTTS3** — 许可最好、CLI+Gradio 完整；**但 pynini/OpenFst 编译地狱 + 只能 Linux + WaveVAE 闸门**。
6. **MaskGCT** — torch 2.0.1 老钉 + espeak-ng + pyopenjtalk + >16GB 显存 + 无 API server + Mac 挂。**最难落地**。

### 7.4 本批 6 个模型的"硬依赖"清单（是否踩坑一览）

| 模型 | fairseq | DeepSpeed | flash-attn | 其他重依赖 / 系统依赖 |
|---|---|---|---|---|
| F5-TTS | ❌ 无 | ❌ 无 | ❌ 无 | FFmpeg；ONNX/MLX 为可选社区路线 |
| Fish-Speech | ❌ 无 | ❌ 无 | ❌ 无 | portaudio19-dev / libsox-dev / FFmpeg；torch==2.8.0 钉死；pyaudio |
| ChatTTS | ❌ 无 | ❌ 无 | ⚠️ 官方**警告不要装** | pynini+WeTextProcessing（仅 Linux）；官方警告别装 TransformerEngine / FlashAttention-2 |
| Spark-TTS | ❌ 无 | ❌ 无 | ❌ 无 | 依赖最少最干净；Python 3.12+ |
| MegaTTS3 | ❌ 无 | ❌ 无 | ❌ 无 | ⚠️ **WeTextProcessing==1.0.4.1 + pynini/OpenFst**（编译地狱）；openai-whisper |
| MaskGCT | ❌ 无 | ❌ 无 | ❌ 无 | ⚠️ **espeak-ng**（必需）+ **pyopenjtalk**（需编译）+ torch==2.0.1 老钉 |

> **好消息：这 6 个模型没有一个硬依赖 fairseq / DeepSpeed / flash-attn。**这正是 2024 年后新一代 TTS 相对 VALL-E/旧 Bark 时代的重要工程进步。

### 7.5 明确标注为「未核实」的项目汇总（供后续补查）

- **F5-TTS**：官方最低/推荐 VRAM；CPU 推理 RTF。
- **ChatTTS**：官方参数量；seed-tts-eval WER/SIM（**该模型从未进入任何论文对比表**）；TTS Arena ELO；INT8/量化；CPU RTF；官方 GGUF 路线成熟度。
- **Fish-Speech**：S2 Pro 的 SIM 数值；S1-mini 的流式/长文本能力；CPU RTF。
- **Spark-TTS**：中文 SIM 之外的情感控制能力；CPU RTF。
- **MegaTTS3**：最低/推荐 VRAM；**中文质量（论文只报英文）**；S2A/ONNX/GGUF 路线。
- **MaskGCT**：官方 CPU RTF；官方 GPU RTF；长文本稳定性；`s2a_model` 精确体积；GGUF 路线。
