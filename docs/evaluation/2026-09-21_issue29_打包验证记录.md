|---|---|
| 内嵌 uv + 绝对路径引用 | ✅ `resolveUv()` 解析顺序：`VOICECLONE_UV_PATH` 覆盖 → 打包内 `Resources/uv/<platform>-<arch>/uv`（sha256 校验通过的 0.12.10）→ PATH 兜底（打包态仅打印告警）。打包后实机启动日志出现 `[main] sidecar ready on port 62447`，sidecar 由内嵌 uv 拉起 |

| uv 版本可复现 | ✅ `UV_VERSION="0.12.10"` 双处钉住 + `src/version-sync.test.ts` 校验一致；下载 URL 走 `releases/download/<tag>/`，`fetch-uv.mjs` 对官方 sha256 全量校验（含镜像路径） |
| 产物 | ✅ macOS：`app/release/VoiceClone-0.1.0-arm64.dmg` + `-mac.zip`（electron-builder，arm64）。Windows：nsis x64 配置与 `dist:win` 脚本就绪（见下方遗留） |

打包内布局已核对：`Contents/Resources/sidecar`（Python 源 + pyproject + uv.lock + 只读 seed data）、`Contents/Resources/uv/darwin-arm64/uv`；可变状态（sidecar-venv、runtime root、用户数据）全部落在 `~/Library/Application Support/voiceclone-app/`。

## 已知限制（不阻塞本工单实现，留人工验收）

1. **未签名**：本机无 Developer ID 证书，dmg/zip 未做 codesign + notarize。未签名 .app 首次启动可能触发 Gatekeeper 提示（右键打开可绕过），并且 macOS 钥匙串访问受限——实测中出现 `Keychain Access Denied (-128)`（`/engines` 的 `keys.get` 路径），签名 + entitlements 后应消失。
2. **Windows 产物未构建**：nsis 配置就绪但需在 Windows 上执行 `npm run dist:win`（NSIS 跨平台构建未验证）。`os.uname` 崩溃已有代码级回归测试，真实 Windows 运行待装机验证。
3. **"无开发环境干净机器"启动**：macOS 侧在开发机上验证了打包态运行（内嵌 uv 自包含、sidecar venv 落 userData，无对 PATH uv 的依赖）；换一台真正干净机器的双盲启动仍需人工执行一次。
