# 交叉试听进 v1，并附带偏好画像与响度归一化

v1 就提供完整的盲听对比：同一个音色 + 同一段文本 → 多个引擎并排生成 → 盲听打分 → 记录成**本地偏好画像**（按语种 / 文本类型统计你在哪个引擎上评分更高）。打分结果**不驱动自动路由**。

**三条绑定关系（它们必须一起存在，所以是一条决定）**：
1. **对比需要公平**：三个云端 + 两个本地引擎的输出电平不一致，不统一响度就并排试听，用户会把"声音更大"误判为"音质更好"。因此**响度归一化（LUFS）是对比功能的内部一致性要求，不是后处理的锦上添花**。
2. **对比需要归一化文本**：若各家自行处理数字与中英混读，比较到的将是"谁的文本处理 bug 更少"，见 ADR-0008。
3. **打分必须有去处**：只存不用的数据不值得采集，因此记录为偏好画像。

**为什么偏好不驱动自动路由**：引擎的可用性（限流、失败重试）、能力覆盖与成本，与"主观偏好"是彼此独立的维度；让偏好静默接管路由会使行为不可预测，并与能力矩阵驱动的路由冲突。偏好画像是**给人看的洞察**，不是调度器。

**为什么这是 v1 而不是 v1.1**：ADR-0001 把音色建成了引擎无关的实体，而"同一个音色换引擎唱一遍"是这个数据模型唯一的价值证明。没有对比功能，第一版看不出它与单引擎工具有何区别。

**Consequence**：盲听对比界面的位置——它属于"生成"标签页内的一个模式，而不是独立页面，因为对比本身是一次生成活动。
