# 0013 — 界面分五个区，用左侧导航；日志抽屉留在生成区内

日期：2026-09-18 · 状态：已采纳 · 关联：plan §2 #18、§6

## 背景

`docs/plan.md` §2 决策 #18 定的是「4 标签页（生成 / 音色库 / 历史 / 设置）」，§6 还给了每页的内容清单——但**从未实现**。`app/src/App.tsx` 是一个 2355 行的单页，按 DOM 顺序渲染八个 `<h2>`：引擎、音色库、转写设置、**生成**、设置、任务队列、历史，外加末尾的日志抽屉。主动作「生成」排在第四，在引擎列表、音色库与转写设置之后。

同时，接下来要落地的四件事都需要一个像样的落点：

- **下载源设置** —— plan §8 列为头号风险的唯一缓解手段，目前完全没有 UI，镜像只能靠未文档化的环境变量触达；
- **本地模型管理** —— ~10GB 的安装进度、磁盘占用、本地权重目录；
- **转写提供方** —— 当前唯一可选项是测试替身，选它会把写死的测试文本写进用户音色库；
- **MiniMax 的数据用途披露** —— ToS 保留「为改进算法或增强服务使用信息」的权利，而这行披露现在几乎不可见（见 ADR-0014）。

把这四件事一起塞进一个「设置」页，会把它变成第二个最长的单页——等于把当前问题换一个地方复现。

## 决策

1. **界面分五个区**：生成、引擎、音色库、历史、设置。相对 plan #18 的 4 页**新增「引擎」区**，承载引擎卡片与安装、能力矩阵、降级顺序、本地模型管理与磁盘占用、下载源。

2. **导航外壳用左侧垂直导航栏**，不用顶部标签条。理由：五个区里「引擎」的内容最长（能力矩阵表格 + 模型管理），垂直导航能容纳图标与文字、并容纳更多条目；同时顶部得以空出来承载**全局状态**——任务队列徽标、日志抽屉开关、连接状态、当前引擎——这些目前散落在页面各处。

3. **各区归属**（改写后回写 plan §6）：

   | 区 | 内容 |
   |---|---|
   | 生成 | 文本输入与归一化预览、音色选择、引擎选择、动态参数面板、生成按钮、结果波形、盲听对比 |
   | 引擎 | 引擎卡片与安装进度、能力矩阵、降级顺序、本地模型管理与磁盘占用、下载源 |
   | 音色库 | 音色卡片、该音色在各引擎上的绑定与健康状态、音色设计、音色包导入导出 |
   | 历史 | 列表与搜索筛选分页、详情、**重跑**（跨区跳转到生成并预填） |
   | 设置 | API Key、转写提供方、存储位置、整库备份恢复、主题与语言、合规 |

4. **日志不单独成区，仍是「生成」区内的可折叠抽屉。** plan §6 那条铁律（生成时用户要盯着日志）不因分区而改变。

5. **跨区行为必须显式改道，不得依赖"同一滚动容器"。** 已核实三处：`rerun()`（历史 → 生成，写 6 个生成区状态并 `scrollIntoView`，分区后目标可能未挂载而静默失效）、`historyRefreshKey`（由生成与任务队列两处推高）、安装动作强制展开日志抽屉的 `setLogsOpen(true)`。另有四处硬编码方位文案（「下方『设置』」「上方『安装引擎』」）在分区后立即成为假话，须改为跳转动作而非方位描述。

6. **引擎选择必须持久化**，不能再是渲染层组件状态（`App.tsx:1220`）。分区之后用户会期待"上次选的引擎还在"。

## 后果

- plan §2 #18「4 标签页」由本 ADR 取代，需回写 plan §2 与 §6。
- 前端目前**零测试**：`app/package.json` 无 test/lint 脚本，依赖里没有 vitest/jest/playwright/testing-library，唯一质量门是 `tsc --noEmit`。这次要动的是**所有页面的组织方式**，因此同批建立最小验证网：把 `api.ts` 之上的数据抓取抽成 hooks（`api.ts` 目前**只有类型、零客户端**，`Authorization` 头在组件里手写约 30 次），配 vitest。
- **契约测试必须走生产构造路径**（`default_registry()`）。既有教训：本地引擎的 `VOICECLONE_*` 覆盖在应用里全部失效，而测试显式传 `env=` 因而通过——测试证明的是产品里不存在的路径。新引擎的测试一律经注册表构造。
- 顺带修掉三处已核实的前端缺陷：`Waveform` 因为 `headers` 对象字面量每次渲染都是新引用、叠加任务队列 2 秒轮询，而被**每 2 秒销毁重建**（播放中途重置）；StrictMode 的 cleanup 因异步 IIFE 在 `await` 之后才赋值 `ws`/`interval`，在逻辑上**不可能生效**（每次挂载泄漏一个 WebSocket 与一个 1 秒轮询器，而代码注释声称相反）；日志 WebSocket 无重连且 `JSON.parse` 无保护。

## 2026 修订：右侧共享侧边栏 + 生成区拆子标签

应用户反馈对布局做两处修订，本 ADR 其余决定不变：

1. **实时日志与任务队列从「生成」「历史」区中独立出来，成为右侧常驻侧边栏**，上下两窗（上：日志，下：任务队列），五个区共享。侧边栏可整体显示/隐藏（导航栏提供显式开关按钮），宽度可拖动，显示状态持久化。日志支持按级别与关键字筛选。原 ADR 第 4 条「日志仍是生成区内的可折叠抽屉」由本条取代；任务队列不再内嵌于历史区。
2. **「生成」区拆为两个子标签：单条生成 / 对比盲听**，二者不共享状态（独立的功能，不是同一流程的两段）。原第 3 条表格中「生成」区的内容归属两个子标签。

同时收敛的界面决定（不属布局，记录在此避免散失）：

- **mlx-whisper 等本地转写工具**在引擎页以正式卡片呈现（安装按钮 + 下载进度条 + 已装状态），安装入口只保留引擎页一处；设置页只保留转写提供方选择。
- **引擎页说明文字收进每张卡片的「详情」展开**，内容按能力矩阵与模型实际能力更新；不支持音色设计的引擎不再出现在音色设计下拉中（原来为禁用显示）。
- **设置页只留软件级设置**（外观、UI 缩放、字号、日志行为、默认下载源、备份恢复）；引擎密钥挪回引擎页卡片，转写 provider 留在设置页。
- **偏好画像刷新按钮与「运行中文回归集」按钮**：偏好画像降级为盲听结果页内的只读汇总（去掉独立刷新按钮）；中文回归集移入引擎页高级区，保留功能并加说明。
- **Fake Engine 仅清理用户可见残留**（能力矩阵 fake 行、占位转写文案），保留 `VOICECLONE_TEST_ENGINES=1` 测试接缝（issue #18 决定不变）。
- **本地引擎安装与转写工具安装统一为字节级下载进度**（步骤状态结构增加进度字段，前端沿用 1 秒轮询）。
