# 不做远程推理，也不做跨机器同步

本地模型只在**安装了本应用的那台机器**上运行。不提供「把这台机器的算力借给另一台」的远程推理服务，也不提供跨机器数据同步。

**为什么这是一个刻意的 no**：项目所有者同时拥有 Apple Silicon Mac（无 NVIDIA）与一台 RTX 3090 主机，显而易见的设计是让 Mac 连上 3090 跑重型模型。选择不做，因此要记录在此，免得未来读者以为这是漏做的功能。

**已知代价（接受）**：
- macOS 端只能运行 torch-free 的轻量引擎（PyTorch/MPS 对 TTS 不可用，见 ADR-0002），重型模型只有 Windows 端能跑。
- 两台机器是两个互不相通的音色库：在 Windows 上克隆的音色不会出现在 Mac 上。

**保留的设计余量**：本机推理服务与远程推理服务在协议上是同一种东西（HTTP + WebSocket），因此将来若要加回远程，属于增加一个地址，而非重构。这条余量不构成当前的工作量。

**仍然提供的两个手动出口**（它们是手动动作，不是持续同步，因此不违背本决定）：
- **音色包导出/导入**：单个音色的元数据 + 头像 + 参考音频 + 参数打包为 `.zip`，用途是**分享给他人**。
- **整库备份/恢复**：整个数据目录的打包与还原，用途是**防丢失**；顺带可用于换机，但那是一次性手动动作。

**数据安全要求（不因本决定而豁免）**：数据目录必须**自包含且可被用户整体拷贝**——SQLite 库、音频文件、音色元数据放在同一个可移植目录下，不散落在系统各处。这是上面两个功能成立的前提，而不是它们的替代品。
