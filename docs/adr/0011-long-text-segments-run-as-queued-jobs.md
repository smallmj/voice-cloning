# 0011 — 长文本分段走任务队列，分段即真实生成记录

日期：2026-09-17 · 状态：已采纳 · 关联：issue #13

## 背景

整篇稿件一次合成会撞上两堵墙：云端单次请求字符上限（计费口径还会把 1 个汉字算作 2 个字符）与本地模型的显存上限。同时厂商限流（429/Throttling）在直发同步请求时表现为用户可见的报错。

## 决策

1. **分段上限由引擎声明，不由编排层猜测。** `Capabilities.max_chars_per_request`（None = 引擎声明无上限，长文本原样直发——分段绝不静默改写行为）。云端 Qwen 引擎保守取 2000 字符：远低于厂商 API 天花板，但长单段韵律会劣化，宁可早切。本地引擎取 500 字符。
2. **切分在句界优先，且必须可往返。** `split_text` 优先按句末标点切，单句超限时退化为子句切分、再退化为定长硬切；`"".join(segments) == text` 是硬保证。
3. **分段任务是显式入队，不是对既有端点的偷换。** `POST /generations` 保持同步语义不变（单段文本行为不变是验收项）；`POST /generations/jobs` 是新的任务入口，前端按「文本长度 > 引擎上限」自动路由，对用户表现为同一次生成。
4. **每个分段是一次真实生成。** 任务不发明新的合成路径——每个分段调用与普通生成完全相同的共享管线，产出独立的 generation 记录（完整 lineage），任务只是把这些记录串起来并把 WAV 拼接成一条完整音频。
5. **限流在管线内重试吸收。** 云端引擎合成抛出匹配限流特征（429/限流/Throttling…）的 `CloudEngineError` 时，按指数退避自动重试（默认 4 次尝试），期间持有每引擎串行锁——单请求串行本身就是限流最自然的解药。其它错误原样上抛。
6. **取消是协作式的。** 排队中的任务取消即永不开始；进行中的任务取消在当前分段结束后生效（分段粒度不可中断），已完成的分段音频拼接保留为部分结果。任务状态本身只存内存——分段记录已在持久历史里，重启不丢真实产物。

## 后果

- 一个 20 段的任务会在历史里出现 20 条 generation 记录 + 1 个拼接产物：lineage 完整，但历史密度变高（`/jobs` 提供聚合视图）。
- 云端健康检查（#12）按分段触发，多次探测会产生少量探测计费（单次 ≈¥0.00016），接受。
- 队列为全局 FIFO 单 worker：多任务天然串行，云端并发压力恒为 1。
